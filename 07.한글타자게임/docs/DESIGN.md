# 「타닥타닥 타자교실」 디자인 스펙 v0.1

> 대상: 10살 여자아이 둘(자매). **데스크톱 전용**, 키보드 필수 (이 게임에 한해 레포의 "터치 입력도 지원" 규칙을 적용하지 않는다. 메뉴는 마우스로도 쓸 수 있다).
> 기반 자료: `docs/RESEARCH.md`. 핵심 기술 결정은 그대로 따른다. **OS 한글 입력기(IME)를 쓰지 않고 `keydown`의 `event.code`를 게임 안의 두벌식 오토마타로 바꾼다.**
> 이 문서의 숫자는 모두 `constants.ts` 초깃값이다. 빌더는 숫자를 새로 정하지 말고 이 값을 상수로 넣는다. 플레이테스트 후 상수만 바꾸면 되게 한다.

## 1. 핵심 루프 (한 문장)

**화면이 가리키는 다음 글자를 보고, 알맞은 손가락으로 그 키를 눌러 글자가 "톡" 하고 완성되는 걸 보는 것을 반복한다. 연습에서는 별을 모으고, 「사탕비 마을」에서는 떨어지는 낱말 사탕을 우산으로 받아 쿠키 마을을 지키며 사탕을 모은다.**

## 2. 모드 구성

메인 메뉴에 큰 버튼 4개가 있고, 아래에 작은 버튼 3개가 있다.

| # | 모드 | 무엇을 하나 | 입력 방식 |
|---|---|---|---|
| 1 | **자리연습** | 8단계. 낱자 하나씩 치며 손가락 자리를 익힌다 | 엄격 모드 |
| 2 | **낱말연습** | 3단계(쉬움/보통/어려움) 중 하나를 골라 낱말 15개 | 엄격 모드 |
| 3 | **짧은 글 연습** | 문장 5개 | 엄격 모드 |
| 4 | **사탕비 마을** | 12단계 떨어지는 낱말 게임(산성비를 귀엽게 바꾼 것). 낱말 사탕을 우산으로 받는다 | 자유 모드 |
| - | 스티커북 | 모은 스티커 보기 | - |
| - | 기록판 | 자매 기록을 나란히 보기(내 기록 중심, 12.7) | - |
| - | 꾸미기 | 모은 사탕으로 우산 색과 쿠키 집 모양 바꾸기(12.4) | - |

긴 글 연습, 통계 그래프 화면, 무한 모드는 **이번 빌드에 넣지 않는다**(8장 참고).

### 2.1 입력 방식 두 가지 (중요)

**엄격 모드 (연습 3종)**
- 목표 문장을 키 순서열로 미리 분해해 둔다(5장 참고). 아이가 키를 누를 때마다 "다음 기대 키"와 비교한다.
- 맞으면 진행한다. 틀리면 **진행하지 않는다.** 틀린 글자는 화면에 들어가지 않고, 오타 수만 1 늘어난다.
- 그래서 Backspace로 지울 것이 없다. 엄격 모드에서 **Backspace는 무시한다**(preventDefault만 한다).
- 화면에 보이는 "친 글자"는 지금까지 맞게 친 키 순서열을 `compose()`로 조합한 결과다. 그래서 "가기"를 칠 때 중간에 "각"이 잠깐 보였다가 ㅣ를 치면 "가기"로 바뀐다. 실제 입력기와 똑같이 보인다.

**자유 모드 (사탕비 마을, 이름 입력)**
- 입력칸에 친 키를 모두 쌓는다(`keys: Jamo[]`). 보이는 글자는 `compose(keys)`의 결과다.
- Backspace를 누르면 마지막 키 하나를 뺀다. "닭"에서 누르면 "달", 한 번 더 누르면 "다"가 된다(실제 입력기처럼 자모 단위로 지운다).
- 자세한 규칙은 6장에 있다.

## 3. 조작 (데스크톱)

| 동작 | 키보드 | 마우스 |
|---|---|---|
| 메뉴 이동 | ← → ↑ ↓ / 숫자 1~4 | 버튼 클릭 |
| 선택 | Enter 또는 Space | 클릭 |
| 뒤로 / 일시정지 | Esc | 왼쪽 위 「← 뒤로」 버튼 |
| 연습 중 글자 입력 | 두벌식 자판 그대로(한/영 상태와 상관없음) | - |
| 쌍자음, ㅒ, ㅖ, !, ? | Shift + 해당 키(왼쪽, 오른쪽 Shift 다 됨) | - |
| 사탕비: 낱말 제출 | 정확히 일치하면 **자동 제출**. Enter나 Space를 눌러도 제출된다 | - |
| 사탕비: 지우기 | Backspace(자모 하나) | - |
| 소리 켜기/끄기 | 없음(키보드 단축키를 두지 않는다. 타자 중에 실수로 눌릴 수 있기 때문) | 오른쪽 위 스피커 아이콘 |
| 키보드 도움 켜기/끄기 | 없음 | 연습 화면 오른쪽 위 「키보드 보기」 토글 |

**Esc 동작**
- 연습 중 또는 사탕비 플레이 중에 누르면 일시정지 창이 뜨고 타이머가 멈춘다. 창에는 「계속하기(Enter)」, 「처음부터(R)」, 「나가기(Esc)」가 있다. Esc를 두 번 누르면 나간다.
- 메뉴나 결과 화면에서 누르면 한 단계 위 화면으로 간다. 프로필 선택 화면에서는 아무 일도 없다.
- 사탕비 플레이 중 창이 포커스를 잃으면(`blur`, `visibilitychange`) 자동으로 일시정지한다.

**Enter 동작**
- 메뉴: 선택.
- 엄격 모드 연습 중: 무시한다. 문장은 다 치면 자동으로 다음으로 넘어간다.
- 결과 화면: 통과했으면 「다음」, 못 했으면 「다시 하기」. R은 항상 「다시 하기」다.
- 사탕비 플레이 중: 제출. 결과 화면에서는 패널이 뜨고 **0.5초 동안 Enter를 받지 않는다**(타자 치던 Enter가 잘못 눌리는 것을 막는다).

## 4. 화면 목록과 배치

### 4.0 공통

- 전체 앱이 **1280×720 고정 무대**다. 창 크기에 맞춰 CSS `transform: scale()`로 비율을 지키며 키우거나 줄이고, 남는 곳은 배경색으로 채운다(레터박스).
- 창이 1024×576보다 작으면 무대 위에 "창을 조금 더 크게 해 주세요"를 띄우고, 옆에 캔버스로 그린 웃는 얼굴을 둔다(이모지는 쓰지 않는다).
- 터치 전용 기기(`matchMedia('(hover: none) and (pointer: coarse)')`)에서는 첫 화면에 "이 게임은 키보드가 있는 컴퓨터에서 할 수 있어요"라는 귀여운 안내만 보여 준다.
- 글꼴은 시스템 글꼴만 쓴다. `"Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif`. 외부 폰트는 쓰지 않는다.
- 화면 전환: 라우트는 `/` 하나다. 화면은 React 상태 `screen`으로 바꾼다.
- 렌더링: **연습 3종과 메뉴는 React DOM과 Tailwind로 만든다**(한글 텍스트와 키보드 배치가 쉽다. 키 입력 하나에 리렌더 한 번이면 충분하다). **사탕비 마을 게임판만 Canvas(1280×720)로 만들고**, 상태는 refs에 둔다. 루프 안에서 React 상태를 쓰지 않는다.

### 4.2 연습 화면(S6) 배치, 1280×720

```
y   0– 64  상단바: [← 뒤로]  모드·단계 이름 | 진행 "7 / 15" + 진행 막대 | 타수 | 정확도 | [키보드 보기] [스피커]
y  80–300  문제 영역(모드별, 아래 참고)
y 320–640  화면 키보드(가운데 정렬)
y 650–710  손가락 안내 띠
```

**문제 영역**
- 자리연습: 낱자 상자 10개(80×80, 간격 12px, 폭 908px 가운데 정렬, 글자 48px 굵게). 지금 칠 상자는 손가락 색 테두리 4px와 위아래 2px 통통 튀는 애니메이션. 친 상자는 연한 회색과 작은 체크. 그 아래 y 220에 "2 / 3 줄"을 작은 점 3개로 보여 준다.
- 낱말연습: 지금 낱말을 y 150 가운데에 72px로 쓴다. 다 친 음절은 진한 색, 지금 음절은 노란 형광 밑줄, 남은 음절은 회색. 오른쪽(x 1000~1240)에 다음 낱말 2개를 32px 회색으로 쓴다. y 250에 친 글자를 56px로 쓰고 끝에 깜빡이는 커서를 둔다.
- 짧은 글: 목표 문장을 y 140에 40px로 쓴다(글자별 색 규칙은 낱말과 같다). 친 글자는 y 210에 40px. 다음 문장은 y 280에 24px 회색.

**화면 키보드**
- 키 한 칸(u)은 58px, 간격 6px. 5줄이다. 숫자 줄(` 1~0 - = ←), Q 줄, A 줄, Z 줄, 스페이스 줄. 줄 시작 위치는 실제 자판과 같다(Tab 1.5u, Caps 1.75u, LShift 2.25u, Space 6.25u).
- 키마다 위에 큰 한글(24px), 아래 구석에 작은 영문(12px)을 쓴다. Shift 글자(ㅃㅉㄸㄲㅆㅒㅖ, !, ?)는 위 오른쪽에 14px로 쓴다.
- 키 바탕은 그 키를 치는 **손가락 색을 20% 진하기로** 칠한다(3.1 표).
- **다음 칠 키**: 바탕을 100% 손가락 색으로 칠하고, 테두리를 흰색 3px로 하고, 0.8초마다 1.0에서 1.08로 커졌다 줄었다 한다. Shift가 필요하면 **반대 손 Shift**도 같이 반짝인다. 왼손 글자(ㅃㅉㄸㄲㅆ, !)는 오른쪽 Shift, 오른손 글자(ㅒㅖ, ?)는 왼쪽 Shift다. 다만 입력은 어느 쪽 Shift든 받는다.
- 누른 키는 120ms 동안 눌린 모양(아래로 2px)을 한다. 틀린 키는 연분홍(#FFC2D1)으로 200ms 보인다.
- F, J 키에는 작은 돌기 막대를 그린다.
- 「키보드 보기」를 끄면 키보드는 남겨 두되 다음 키 하이라이트만 끈다. 이 설정은 프로필마다 저장하고, 기본값은 켜짐이다.

**손가락 안내 띠**: 동그라미 10개(지름 40px)를 왼손 새끼, 약지, 중지, 검지, 엄지 | 엄지, 검지, 중지, 약지, 새끼 순서로 놓고 각각 손가락 색으로 칠한다. 아래에 "새끼", "약지" 같은 이름표를 단다. 지금 써야 할 손가락은 1.3배로 커지고 빛난다.

### 4.3 연습 결과(S7)

- 가운데 카드(760×520). 별 3개 자리를 보여 주고, 얻은 별을 0.25초 간격으로 "통" 소리와 함께 채운다.
- 큰 숫자 두 개: **타수**와 **정확도**. 작게 걸린 시간 "1분 12초".
- 「새 기록!」 리본: 이 모드와 단계에서 최고 타수를 넘었을 때.
- **자주 틀린 키 상위 3개**: 작은 키보드 그림에서 그 키를 연분홍으로 칠하고 "ㄹ 3번" 식으로 적는다. 오타가 0개면 "실수 0개! 완벽해요" 문구를 보여 준다.
- **최근 5판 타수 막대그래프**(같은 모드·단계, 이번 판은 진한 색). 실력이 느는 것이 눈에 보인다.
- 버튼: 「다음 단계(Enter)」(통과했고 다음 단계가 있을 때), 「다시 하기(R)」, 「메뉴(Esc)」. 통과하지 못했을 때 Enter는 「다시 하기」다.
- 문구: 통과하면 "멋져요!", "손가락이 척척!", "타닥타닥 달인!" 중 하나를 무작위로. 통과 못 하면 "조금만 더! 한 번 더 해 볼까요?" **혼내는 말은 쓰지 않는다.**

## 5. 두벌식 처리 (빌더용 정확한 규칙)

### 5.1 키 매핑 (`event.code` → 자모)

```
기본:  KeyQ ㅂ KeyW ㅈ KeyE ㄷ KeyR ㄱ KeyT ㅅ KeyY ㅛ KeyU ㅕ KeyI ㅑ KeyO ㅐ KeyP ㅔ
       KeyA ㅁ KeyS ㄴ KeyD ㅇ KeyF ㄹ KeyG ㅎ KeyH ㅗ KeyJ ㅓ KeyK ㅏ KeyL ㅣ
       KeyZ ㅋ KeyX ㅌ KeyC ㅊ KeyV ㅍ KeyB ㅠ KeyN ㅜ KeyM ㅡ
Shift: KeyQ ㅃ KeyW ㅉ KeyE ㄸ KeyR ㄲ KeyT ㅆ KeyO ㅒ KeyP ㅖ
       (나머지 글자 키는 Shift를 눌러도 기본 자모다. Shift+A = ㅁ)
기호:  Space " "   Period "."   Comma ","   Shift+Digit1 "!"   Shift+Slash "?"
```
- 위 표에 없는 키(숫자, 다른 기호, F키 등)는 엄격 모드에서 **무시**한다. 오타로 세지 않는다. 자유 모드에서도 무시한다.
- `event.ctrlKey || event.metaKey || event.altKey`이면 **아무것도 하지 않고 기본 동작을 그대로 둔다**(Cmd+R 새로고침, Cmd+Q 등은 돼야 한다).
- `event.repeat === true`(키를 꾹 누르고 있을 때)는 **무시한다**. 오타로도, 타수로도 세지 않는다.
- 처리한 키, 그리고 Space, Backspace, Tab, Slash, Quote, Enter는 `preventDefault()`로 막는다. 스크롤, 뒤로 가기, Firefox 빠른 찾기를 막기 위해서다.
- 키 입력은 `window`의 `keydown`에서 받는다. **게임 화면에는 `<input>`이나 `contenteditable`을 절대 두지 않는다.** 포커스가 입력 요소에 있으면 OS 입력기가 끼어든다. 이름 입력도 자체 오토마타로 받는다.

### 5.2 자모 표

```
초성(19): ㄱ ㄲ ㄴ ㄷ ㄸ ㄹ ㅁ ㅂ ㅃ ㅅ ㅆ ㅇ ㅈ ㅉ ㅊ ㅋ ㅌ ㅍ ㅎ
중성(21): ㅏ ㅐ ㅑ ㅒ ㅓ ㅔ ㅕ ㅖ ㅗ ㅘ ㅙ ㅚ ㅛ ㅜ ㅝ ㅞ ㅟ ㅠ ㅡ ㅢ ㅣ
종성(28): (없음) ㄱ ㄲ ㄳ ㄴ ㄵ ㄶ ㄷ ㄹ ㄺ ㄻ ㄼ ㄽ ㄾ ㄿ ㅀ ㅁ ㅂ ㅄ ㅅ ㅆ ㅇ ㅈ ㅊ ㅋ ㅌ ㅍ ㅎ
음절 = 0xAC00 + (초성×21 + 중성)×28 + 종성
겹모음: ㅗ+ㅏ=ㅘ ㅗ+ㅐ=ㅙ ㅗ+ㅣ=ㅚ ㅜ+ㅓ=ㅝ ㅜ+ㅔ=ㅞ ㅜ+ㅣ=ㅟ ㅡ+ㅣ=ㅢ
겹받침: ㄱ+ㅅ=ㄳ ㄴ+ㅈ=ㄵ ㄴ+ㅎ=ㄶ ㄹ+ㄱ=ㄺ ㄹ+ㅁ=ㄻ ㄹ+ㅂ=ㄼ ㄹ+ㅅ=ㄽ ㄹ+ㅌ=ㄾ ㄹ+ㅍ=ㄿ ㄹ+ㅎ=ㅀ ㅂ+ㅅ=ㅄ
종성이 될 수 없는 자음: ㄸ ㅃ ㅉ
두벌식 표준: ㄱ+ㄱ는 ㄲ가 되지 않는다(ㄲ는 Shift+R로만 친다).
```

### 5.3 `decompose(text) → Key[]` (목표를 키 순서열로)

음절마다 초성 키 1개, 중성 키 1~2개(겹모음은 두 키로 나눈다), 종성 키 0~2개(겹받침은 두 키로 나눈다)를 넣는다. 쌍자음, ㅒ, ㅖ는 **Shift가 붙은 키 1개**다. 공백과 기호는 키 1개다.
예: `닭` → [ㄷ, ㅏ, ㄹ, ㄱ] / `과자` → [ㄱ, ㅗ, ㅏ, ㅈ, ㅏ] / `있어요` → [ㅇ, ㅣ, ⇧ㅆ, ㅓ, ㅇ, ㅛ]
`Key = { code: string; shift: boolean; jamo: string }`. 키 하나가 1타다.

### 5.4 `compose(jamos) → string` (순수 함수, 엄격 모드와 자유 모드가 함께 쓴다)

현재 음절 `cur = {cho?, jung?, jong?}`과 확정된 문자열을 두고 자모를 하나씩 넣는다.

**자음 C가 들어오면**
1. `cur`가 비었으면 `cho=C`.
2. `cho`만 있거나 `jung`만 있으면(초성 없는 모음) `cur`를 확정하고 `cho=C`.
3. `cho`와 `jung`이 있고 `jong`이 없으면: C가 종성이 될 수 있으면 `jong=C`. 아니면(ㄸㅃㅉ) 확정하고 `cho=C`.
4. `jong`이 있으면: `jong+C`가 겹받침이면 `jong=겹받침`. 아니면 확정하고 `cho=C`.

**모음 V가 들어오면**
1. `cur`가 비었으면 `jung=V`(초성 없는 모음).
2. `cho`만 있으면 `jung=V`.
3. `jung`이 있고 `jong`이 없으면: `jung+V`가 겹모음이면 합친다. 아니면 확정하고 새 `cur={jung:V}`.
4. `jong`이 있으면 **종성을 옮긴다**: 겹받침이면 앞 자음을 남기고 뒤 자음을 떼어 새 음절 초성으로 보낸다(`닭`+ㅏ → `달가`). 홑받침이면 통째로 새 음절 초성으로 보낸다(`각`+ㅏ → `가가`, `있`+ㅓ → `이써`). 그 뒤 새 음절 `jung=V`.

**기호(공백, 점 등)가 들어오면**: `cur`를 확정하고 기호를 붙인다.

**출력**: `cho+jung(+jong)`은 완성형 음절로 바꾼다. `cho`만 있으면 호환 자모(ㄱ, U+3131 영역), `jung`만 있으면 호환 모음(ㅏ)으로 쓴다.

**자유 모드 Backspace** = `keys.pop()` 후 `compose(keys)`를 다시 한다. 상태를 따로 두지 않는다. 이 방식이면 버그가 거의 생기지 않는다.

**단위 테스트**(빌더가 반드시 넣는다): `compose(decompose(w)) === w`를 모든 낱말과 문장으로 확인한다. 추가로 `ㄷㅏㄹㄱㅏ`→`달가`, `ㄱㅗㅏ`→`과`, `ㅇㅣ⇧ㅆㅓ`→`이써`, `ㄱㄱ`→`ㄱㄱ`, `ㅏㄱ`→`ㅏㄱ`.

## 6. 측정: 타수와 정확도

- **타(키 입력 1개)**: 5.3의 키 하나. 쌍자음(Shift+키)도 1타, 공백도 1타, 기호도 1타다.
- **맞은 타 `correct`**: 엄격 모드에서 기대 키와 같았던 입력 수(= 목표 키 순서열 길이).
- **틀린 타 `wrong`**: 매핑 표에 있는 키인데 기대 키와 달랐던 입력 수. 무시하는 키, repeat, 단독 Shift는 세지 않는다.
- **걸린 시간 `t`(초)**: 그 판 **첫 키(맞든 틀리든)를 누른 순간부터 마지막 맞은 키까지**. 일시정지한 시간은 뺀다. 낱말과 문장이 바뀌는 사이에 기다리는 시간은 없다(바로 넘어간다).
- **타수(CPM)** = `round(correct × 60 / t)`.
- **정확도(%)** = `round(correct / (correct + wrong) × 100)`. 아직 친 키가 없으면 100으로 둔다.

**플레이 중 표시**: 상단바에 "타수 87타", "정확도 96%"를 보여 준다. 타수는 0.5초마다 다시 계산하고, **처음 3초 동안은 "--"**로 둔다(처음 몇 키 때문에 숫자가 크게 튀는 걸 막는다). 정확도는 키를 누를 때마다 바로 바꾼다.

**사탕비 마을**은 정확도를 재지 않는다(자유 입력이라 기준이 애매하다). 결과에 `타수 = 받은 낱말의 키 수 합 × 60 / 플레이 시간(일시정지·얼음 시간 제외)`만 보여 준다.

**자리연습**은 타수를 보여 주되 별 기준에는 쓰지 않는다(자리를 익히는 단계라 속도를 재촉하지 않는다).

## 7. 틀린 키를 눌렀을 때 (부드럽게)

- 소리: 낮고 둥근 "뽁". triangle 파형 260Hz에서 200Hz로 내려가며 90ms, 음량 0.06. **버저나 경고음은 쓰지 않는다.**
- 화면: 지금 칠 글자(자리 상자나 음절)가 좌우로 4px, 150ms 동안 살짝 흔들리고 밑줄이 연분홍으로 바뀐다. 화면 키보드에서는 누른 키를 연분홍으로 200ms, 정답 키는 더 크게 1.15배로 한 번 튀게 한다.
- 같은 글자에서 **3번 연달아 틀리면** 말풍선으로 손가락을 알려 준다. "**왼손 검지**로 **ㄹ**!" 손가락 띠에서 그 손가락이 1.5배로 커진다. 맞게 치면 말풍선이 사라진다.
- **Shift 실수 안내**: 기대 키는 Shift가 없는데 Shift를 누른 채 쳐서 틀린 일이 2번 연속이면 "Shift에서 손을 떼 볼까요?"를 보여 준다. 반대로 Shift가 필요한데 없이 쳐서 2번 연속 틀리면 "Shift를 같이 눌러요!"를 보여 주고 Shift 키를 반짝인다.
- 맞은 키: 아주 작은 "톡". sine 880Hz, 30ms, 음량 0.04. 낱말이나 문장 하나를 끝내면 "띵동" 두 음(C6 → E6, 각 80ms).

### 8.2 한 판 구성

- 한 판은 **3줄 × 10글자 = 30타**다.
- 문제 만들기: (1) 새 키를 하나도 빠짐없이 **최소 3번씩** 넣는다(1~3단계는 그 단계 키 전부를 최소 3번씩). (2) 남은 자리는 위 비율로 무작위로 채운다. (3) 섞는다. (4) **같은 키가 3번 연달아 나오지 않게** 다시 섞는다.
- 줄을 다 치면 0.3초 동안 줄이 반짝이고 다음 줄로 넘어간다(이 시간은 걸린 시간에서 뺀다).

### 8.3 통과 기준과 별

| 결과 | 기준(정확도만 본다) |
|---|---|
| ★★★ | 정확도 98% 이상(30타에 오타 0개) |
| ★★ | 95% 이상(오타 1개) |
| ★ (통과) | 85% 이상(오타 5개까지) |
| 다시 해 봐요 | 85% 미만. 별은 없지만 기록은 남기고 바로 다시 할 수 있다 |

- 다음 단계는 앞 단계를 ★ 1개 이상으로 통과하면 열린다. 1단계는 처음부터 열려 있다.
- 정확도 100%로 끝내면 결과 화면이 뜨기 전에 화면 키보드가 왼쪽에서 오른쪽으로 무지개 물결을 0.8초 동안 그린다(숨은 보상이다).

## 11. 사탕비 마을 (대표 게임)

> audience 의견을 반영했다. 테마는 **사탕비**다. 낱말이 적힌 사탕이 쿠키 마을에 떨어지고, 나는 **우산**으로 쿠키 마을을 지킨다. 낱말을 치면 사탕을 받는다. 받은 사탕은 모아서 꾸미기에 쓴다. 지루한 경우("낱말만 떨어지고 아무것도 안 바뀜")를 막으려고 단계마다 새 요소, 배경, 사탕 모양을 바꾼다(11.8).

### 11.1 이야기와 테마

솜사탕 구름 **「뿌뿌」**는 감기에 걸려 "에취!" 할 때마다 낱말이 적힌 **사탕**을 쏟는다. 뿌뿌는 나쁜 구름이 아니다. 코가 간질간질할 뿐이다. 땅에는 **쿠키 집 8채**가 있는 쿠키 마을이 있다. 사탕이 쿠키 집 지붕에 떨어지면 집이 **끈적끈적 사탕 범벅**이 된다. 지붕에 사탕 시럽이 흘러내리고, 집 얼굴이 "으앙, 끈적해~" 하는 웃긴 표정을 짓는다. 낱말을 치면 내 **우산**이 슝 날아가 사탕을 받아 내고, 사탕은 화면 위 **사탕 병**으로 쏙 들어간다. 12단계를 모두 깨면 뿌뿌의 감기가 낫고 고맙다며 진짜 사탕 선물을 비처럼 내려 준다.

무서운 것은 하나도 없다. 실패해도 "마을이 달콤 범벅이 됐어요"일 뿐이다.

### 11.2 규칙

- **쿠키 집 8채**로 시작한다. 단계마다 8채 모두 깨끗하게 다시 시작한다(단계끼리 이어지지 않는다).
- 사탕(라벨 중심)이 y ≥ 590에 닿으면 "놓침"이다. 그 사탕의 x에서 **가장 가까운 깨끗한 집** 한 채가 사탕 범벅이 된다. 사탕은 "철퍼덕" 하고 시럽 자국을 남긴다.
- 8채가 모두 사탕 범벅이 되면 실패다(11.6).
- 그 단계 **목표 수**만큼 사탕을 받으면 성공이다. 황금 사탕과 「커다란 우산」으로 받은 사탕도 센다.
- **입력**: 자유 모드다. 입력한 키 순서열이 화면에 있는 사탕 낱말의 키 순서열과 **정확히 같아지는 순간 자동으로 받는다**. 같은 낱말이 두 개면(생성 규칙상 생기지 않지만) 땅에 더 가까운 것을 받는다. 받으면 입력칸을 비운다.
- **받는 연출**(보기만 하는 것): 땅 위 y=560에 있는 내 우산(프로필 동물이 우산을 들고 있다)이 0.15초 만에 그 사탕 x로 미끄러져 가서 우산을 펼친다. 사탕은 게임 판정상 **입력하는 순간 바로 사라진다.** 우산 이동은 판정에 영향을 주지 않는다. 받은 사탕은 0.4초 동안 포물선을 그리며 HUD의 사탕 병으로 날아간다.
- **Enter나 Space**: 맞는 사탕이 없으면 입력칸을 흔들고(150ms) 비운다. 소리는 부드러운 "뽁"이다. 콤보만 0이 되고 다른 벌은 없다.
- **미리 보기**: 입력 키 순서열이 어떤 사탕 낱말 키 순서열의 앞부분과 같으면 그 사탕에 흰 테두리 3px와 반짝임을 준다. 어느 사탕과도 맞지 않으면 입력칸 글자를 연분홍으로 바꾼다(벌은 없다).
- 입력칸은 키 14개까지 받는다. 그보다 많으면 무시한다.

### 11.3 사탕 생성

- 생성 위치: y=110, x는 라벨이 60~1220 안에 들어가도록 무작위다. 이미 y<200에 있는 사탕과 가로로 겹치면 다시 뽑는다(최대 8번).
- 라벨: 흰 알약 모양. 폭은 글자 폭+28px, 높이 46px, 글자 30px 굵게. 라벨 위에 사탕 그림(약 34px)이 붙어 있다.
- 일반 사탕 모양 4종: 동그란 알사탕, 막대사탕, 젤리곰, 리본 포장 캐러멜. 무작위로 고른다. 색은 하늘 #8FD3FF, 연보라 #C9B6FF, 민트 #9EF0D0, 분홍 #FFB3D1 중 무작위. **노랑, 금색, 주황은 일반 사탕에 절대 쓰지 않는다.**
- 황금 사탕(「반짝 별사탕」): 금색 #FFD43B **별 모양** 사탕. 반짝이 4개가 돌고, 라벨 테두리는 금색 3px다. 별 모양은 황금 사탕에만 쓴다. 낱말은 언제나 **쉬움** 단계에서 뽑는다.
- 사탕은 떨어지면서 ±6도로 천천히 흔들린다(주기 2초). 라벨 글자는 기울이지 않는다(읽기 쉽게).
- **간격**: 단계표의 `spawnInterval`초마다 하나. 화면에 사탕이 하나도 없으면 0.8초 뒤에 바로 다음 사탕을 만든다(빨리 치는 아이가 기다리지 않게).
- `maxOnScreen`에 이르면 하나가 사라질 때까지 생성을 미룬다.
- **쌍둥이 사탕**(8단계부터): 생성할 때 `twinChance` 확률로 사탕 2개를 동시에(x를 서로 300px 이상 떨어뜨려) 만들고, 다음 간격을 ×1.6으로 늘린다. 쌍둥이 둘은 같은 모양과 같은 색으로 그린다.
- **겹침 금지 규칙**: 새 낱말의 키 순서열이 화면에 있는 어떤 사탕의 키 순서열과 앞부분이 겹치면(한쪽이 다른 쪽의 접두사이면) 그 낱말은 쓰지 않는다. 같은 낱말도 쓰지 않는다. 자동 제출이 엉뚱한 사탕을 받는 일을 막는 규칙이다.
- 뿌뿌는 x 200~1080 사이를 18px/s로 오가다가 사탕을 만들 때마다 0.3초 동안 "에취!"를 한다(보기만 하는 것이고, 생성 x와는 관계없다).
- 낱말은 단계별 셔플백에서 뽑는다.

### 11.5 황금 별사탕 효과 (좋거나 웃기기만 하다. 벌칙은 없다)

황금 사탕을 받으면 아래에서 가중치대로 하나를 고른다. 화면 위쪽 가운데에 1.5초 동안 큰 배너(이름과 한 줄 설명)가 뜬다. **황금 사탕을 놓쳐도 집은 범벅이 되지 않는다.** 땅에 닿으면 반짝이며 사라진다.

| 효과 | 가중치 | 무엇이 되나 |
|---|---|---|
| 커다란 우산 | 20 | 하늘을 덮는 큰 우산이 펼쳐져 화면의 모든 사탕을 한꺼번에 받는다. 목표 수에 모두 세고, 점수는 사탕마다 절반을 받는다 |
| 느릿느릿 달팽이 | 18 | 6초 동안 떨어지는 속도가 ×0.5. 화면 아래에서 젤리 달팽이가 기어간다 |
| 사탕 둥실 | 18 | 4초 동안 모든 사탕에 작은 풍선이 달려 멈추고, 생성도 멈춘다 |
| 쿠키 집 청소 | 16 | 꿀벌 청소부가 날아와 범벅이 된 집 한 채를 깨끗하게 한다(왼쪽부터). 범벅 집이 없으면 「무지개 두 배」로 바꾼다 |
| 무지개 두 배 | 14 | 다음 5개 낱말 점수와 사탕이 ×2. HUD에 무지개 아이콘과 남은 수를 보여 준다 |
| 뿌뿌 에취쇼 | 14 | 뿌뿌가 크게 재채기하며 색종이를 뿌린다(웃긴 효과). 모든 사탕이 **위로 80px** 밀려 올라간다(y는 110 아래로 내려가지 않는다) |

- 같은 효과가 이미 진행 중이면 남은 시간을 새로 고친다(시간이 쌓이지 않는다).

### 11.6 점수, 별, 사탕, 끝

- 낱말 점수 = `10 × 키 수 × 콤보배율 × (무지개면 2)`
- 콤보배율 = `1 + 0.1 × min(콤보, 10)`(최대 ×2.0). 콤보는 받을 때마다 +1, 놓치거나 틀린 제출을 하면 0이 된다. 콤보가 5 이상이면 HUD 점수 옆에 "콤보 7!"을 보여 준다.
- 성공 보너스 = `깨끗한 집 수 × 50`
- 받을 때 그 자리에 "+84" 같은 숫자가 위로 0.6초 떠오른다.
- **별**(놓친 수 기준): 0~1개 ★★★ / 2~4개 ★★ / 5~7개 ★. 별을 하나라도 받으면 다음 단계가 열린다.
- **사탕(꾸미기 화폐, 12.4)**: 일반 사탕 1개 = 사탕 1, 황금 별사탕 = 사탕 5, 무지개 두 배 중에는 ×2. 성공하면 `깨끗한 집 수`만큼 더 준다. **실패해도 그 판에서 받은 사탕은 모두 가진다.**

**성공**: 목표 수에 닿으면 남은 사탕이 모두 반짝이로 사라지고(점수 없음), 깨끗한 집들이 1.5초 동안 폴짝폴짝 춤을 춘다. 그다음 결과 패널이 뜬다. 패널에는 별, 점수, 받은 사탕 수, 최고 콤보, 타수, 「내 새 기록!」이 있다. 버튼은 「다음 단계(Enter)」, 「다시(R)」, 「단계 선택(Esc)」이다. 패널은 아이가 누를 때까지 기다린다(자동으로 넘어가지 않는다).

**실패(8채 모두 사탕 범벅)**: 목표는 "**내일 또 해 볼래!**"라는 기분이 드는 것이다.
- 0.0초: 생성이 멈추고, 남은 사탕은 천천히 흐려진다. 뿌뿌가 "앗, 미안~ 에취!" 하며 머쓱해한다. 쿠키 집들은 끈적한 채로 깔깔 웃는다(슬퍼하지 않는다).
- 1.0초: 패널이 뜬다. 제목은 "마을이 달콤 범벅이 됐어요!" 그 아래에 크게 "**사탕 23개는 내 거!**"(이번 판에 받은 사탕), "다음 꾸미기까지 사탕 37개"와 진행 막대(12.4에서 아직 안 산 것 중 가장 싼 것 기준), 이번 판 점수와 내 최고 기록을 보여 준다. 문구는 "또 해 볼까?", "내일은 더 많이 받을 수 있어!" 중 하나를 무작위로.
- 「다시 하기(Enter)」에 포커스를 둔다. **1.5초부터 Enter를 받는다** → 같은 단계를 깨끗한 집 8채로 바로 다시 시작한다(카운트다운 없음). 실패에서 다시 플레이까지 **2초 안**이다. 「꾸미러 가기(C)」 버튼도 있다.
- 실패한 판의 점수도 최고 기록 후보에 넣는다.

**단계 시작**: "3단계 · 젤리 언덕"을 0.8초 보여 준 뒤 바로 첫 사탕을 만든다.

### 11.7 엔딩 (12단계 성공)

결과 패널 대신 S11을 보여 준다. 뿌뿌가 "고마워! 이제 감기 다 나았어! 이건 진짜 선물이야~" 하며 하늘에 무지개를 그리고, 사탕 소나기를 5초 동안 내린다(치지 않아도 자동으로 병에 들어간다. **보너스 사탕 50**). 쿠키 집 8채가 활짝 웃고 "쿠키 마을의 영웅 {이름}!"이 뜬다. 스티커를 하나 준다. Enter를 누르면 단계 선택으로 간다.

### 11.8 "계속 뭔가 바뀐다" 장치 (지루함 방지, 모두 보기만 하는 것이라 만들기 쉽다)

- 두 단계마다 배경이 바뀐다(11.4 표의 7종).
- 사탕 모양 4종과 색 4종을 무작위로 섞는다.
- 뿌뿌의 반응: 콤보 5에서 "히히!", 콤보 10에서 "우와아!"(말풍선 1초), 황금 사탕을 받으면 눈이 하트가 된다(1초).
- 내 우산: 콤보 5 이상이면 반짝이 꼬리가 생기고, 콤보 10 이상이면 무지개 꼬리가 생긴다.
- 쿠키 집: 바로 위의 사탕을 받아 주면 그 집이 0.5초 동안 "고마워!" 하고 폴짝 뛴다.
- 단계 안에서 목표의 50%를 채우면 배경 음악에 반짝 소리 한 층이 더해진다.

## 12. 진행과 보상

### 12.1 프로필

- 최대 4개. 카드에는 동물 얼굴(캔버스로 그림: 토끼, 고양이, 강아지, 곰, 펭귄, 다람쥐), 이름, 총 별, 가진 사탕 수가 있다.
- 이름은 자유 모드 오토마타로 받는다. 1~5글자 한글(음절이나 낱자). Backspace로 지우고 Enter로 정한다. 비어 있으면 Enter가 안 된다. 같은 이름이 있으면 "이미 있는 이름이에요"를 보여 준다.
- 프로필 지우기: 카드 오른쪽 위 작은 「···」 → "정말 지울까요?" → 「지우기」 클릭만 된다(키보드 Enter로는 지울 수 없게 해서 실수를 막는다).
- 마지막으로 쓴 프로필이 S1에서 먼저 선택되어 있다. Enter 한 번이면 들어간다.

### 12.2 별

- 자리연습 8×3 = 24개, 낱말 3×3 = 9개, 짧은 글 3개, 사탕비 12×3 = 36개. 모두 합쳐 **72개**.
- 각 칸에는 받은 별 중 **가장 많은 수**를 남긴다. 메인 메뉴에 "★ 31 / 72"를 보여 준다.

### 12.3 연속 연습

- 하루(로컬 날짜)에 아무 판이나 하나를 끝까지 하면 그날을 셈한다. 메인 메뉴에 "3일째 연습 중!"과 작은 도장 7개(이번 주)를 보여 준다. 하루를 걸러도 벌은 없다. 숫자만 1부터 다시 센다.

### 12.4 사탕과 꾸미기(S14) — 가벼운 꾸미기

**사탕을 버는 방법**
- 사탕비에서 받은 사탕(11.6).
- 연습 3종: 한 판을 끝낼 때마다 `그 판에서 받은 별 수 × 3` 사탕(최대 9). 처음 받는 별이 아니어도 준다. 연습을 해도 꾸미기가 된다.
- 결과 화면에는 늘 "사탕 +12"를 사탕 병 그림과 함께 보여 준다.

**꾸미기 가게(S14)**: 메인 메뉴의 「꾸미기」 버튼으로 들어간다. 탭은 2개다. 왼쪽에 미리 보기(쿠키 집 한 채와 우산을 든 내 동물)가 있고, 오른쪽에 4열 격자가 있다. 가진 것을 누르면 바로 장착하고, 안 가진 것을 누르면 "사탕 30개로 살까요?" → 「살래요」 / 「아니요」를 묻는다. 사탕이 모자라면 버튼을 회색으로 하고 "사탕 12개 더 모으면 돼요!"라고 쓴다.

### 12.5 우리 집 사탕 병 (함께 모으기 — 싸움 방지 장치)

- 모든 프로필이 **지금까지 번 사탕 합계**(쓴 것도 빼지 않는다)를 하나의 큰 병에 모은다. 메인 메뉴 오른쪽과 기록판 맨 위에 보여 준다.
- 함께 모은 양이 아래에 닿으면 **모든 프로필**에게 장식이 열린다. 열릴 때 "우리 집 사탕 병이 500개가 됐어요! 무지개 다리가 생겼어요"라는 카드가 1.5초 동안 뜬다.

| 500 | 사탕비 마을 뒤에 무지개 다리 장식 |
| 1,500 | 마을 가운데에 도는 사탕 회전목마 |
| 3,000 | 단계 성공 때 불꽃놀이(사탕 모양) |
| 6,000 | 금빛 우산(우산 #8, 모두 공짜로 받음) |

- 그 아래 프로필마다 카드 하나를 나란히 둔다. 카드 안에는 아바타와 이름, 낱말 최고 타수, 짧은 글 최고 타수, 사탕비 최고 단계, 총 별, 스티커 수, 연속 일수가 있다.
- **1등, 왕관, 순위 표시는 두지 않는다.** 대신 카드마다 "**이번 주에 늘었어요 +12타**" 배지를 단다. 값은 이번 주(월요일부터) 낱말 최고 타수에서 지난주까지의 낱말 최고 타수를 뺀 것이다. 0 이하이면 배지 대신 "이번 주도 화이팅!"을 쓴다. 비교 대상이 언제나 **어제의 나**가 되게 한다.
- 결과 화면(S7, S10)의 「새 기록!」도 **내 기록**하고만 비교한다. 다른 프로필 기록은 결과 화면에 나오지 않는다.

### 12.8 localStorage

키 하나 `tadak.v1`에 JSON 하나를 저장한다. 판이 끝날 때마다, 그리고 프로필, 설정, 꾸미기를 바꿀 때마다 저장한다. 파싱에 실패하면 새 데이터로 시작한다(앱이 멈추지 않게).

```ts
type Save = {
  version: 1;
  lastProfileId: string | null;
  sound: boolean;
  familyCandies: number;          // 모든 프로필이 번 사탕 누적(줄지 않음)
  profiles: Profile[];
};
type Profile = {
  id: string; name: string; avatar: 0|1|2|3|4|5; color: 0|1|2|3|4|5; createdAt: number;
  showKeyHint: boolean;
  candies: number;                // 지갑(쓰면 줄어듦)
  owned: { umbrella: number[]; house: number[] };   // 처음 값 [0], [0]
  equipped: { umbrella: number; house: number };
  stars: { jari: number[]; word: number[]; sentence: number; rain: number[] }; // 8, 3, 1, 12
  best: { jariAcc: number[]; wordCpm: number[]; sentenceCpm: number; rainScore: number[]; rainLevel: number };
  weeklyWordBest: { [mondayYyyyMmDd: string]: number }; // 최근 8주만 보관
  recentCpm: { [key: string]: number[] }; // "jari-3", "word-1", "sentence", "rain-7" → 최근 20개
  stickers: { id: number; at: number; seen: boolean }[];
  totalKeys: number;
  daily: { [yyyyMmDd: string]: number }; // 그날 맞은 타 수(최근 14일만 보관)
  streak: { last: string; days: number };
};
```

## 13. 한/영, CapsLock, Shift 예외 처리

- **한/영 상태**: `event.code`만 보므로 OS 입력 소스가 영문이든 한글이든 **항상 한글이 나온다.** 화면 어디에도 "한/영을 바꾸세요" 같은 안내가 필요 없다. 한국어 입력기가 켜져 있으면 브라우저가 `event.key === "Process"`나 `keyCode 229`를 줄 수 있지만 **`event.key`와 `keyCode`는 쓰지 않는다.** `event.isComposing`도 보지 않는다(입력 요소가 없으니 실제 조합은 생기지 않는다).
- **한/영 키 자체**: `Lang1`, `Lang2`, `HangulMode`, `HanjaMode`, `AltRight`(한국 자판의 한/영), `CapsLock`(macOS에서 입력 소스 전환)은 모두 **무시한다.** 오타로 세지 않는다.
- **CapsLock**: `getModifierState('CapsLock')`을 **쓰지 않는다.** CapsLock이 켜져 있어도 ㄱ은 ㄱ이다. 쌍자음은 오직 `event.shiftKey`로 정한다. 그래서 CapsLock 때문에 쌍자음이 잘못 나오는 일이 없다.
- **Shift 단독 keydown**(`ShiftLeft`, `ShiftRight`): 무시한다(오타 아님). 화면 키보드 Shift 키만 눌린 모양으로 그린다.
- **Shift를 누르고 Shift가 없는 키**: 5.1 규칙대로 기본 자모로 친다(Shift+A = ㅁ). 그래서 Shift를 오래 누르고 있어도 ㅁ, ㄴ 같은 글자는 맞다. ㄱ→ㄲ처럼 Shift 짝이 있는 키만 틀린다. 7장의 Shift 안내가 이 경우를 다룬다.
- **Ctrl, Alt, Meta 조합**: 처리하지 않는다(5.1).
- **창 포커스**: 사탕비는 `blur` 때 일시정지한다. 연습은 `blur` 때 시간을 멈추고, 돌아오면 이어서 잰다.
- **Windows Shift+Space**(한/영 전환으로 설정된 PC): Shift+Space는 그냥 공백 1타로 받는다.

## 14. 소리 (Web Audio, 파일 없음)

- AudioContext는 첫 `click`이나 `keydown` 핸들러 안에서 `resume()`한다(데스크톱이지만 Safari도 같은 규칙이다).
- 효과음: 맞은 키 "톡", 틀린 키 "뽁"(7장), 낱말 완료 "띵동", 별 하나 "통"(C5, 120ms), 사탕 받음 "퐁"(sine 600→1200Hz, 80ms)과 병에 들어갈 때 "딸랑"(sine 1500Hz, 40ms), 놓침 "철퍼덕"(sine 500→300Hz, 200ms, 부드럽게), 황금 효과 실로폰 3음 위로 올라가기, 성공 팡파레 5음(C E G C' E'), 실패 "뿌우~"(웃긴 내림음, triangle 400→250Hz, 400ms).
- 배경음: 사탕비에서만 잔잔한 4마디 반복(BPM 96, 메이저 펜타토닉). 단계 11~12는 BPM 104. 연습에는 배경음이 없다(집중을 위해서다).
- 소리는 스피커 아이콘 하나로 끄고 켠다. 이 설정은 `Save.sound`에 저장한다.

## 18. 열린 질문 (플레이테스트로 정할 것)

1. **아이들의 실제 타수**: 사탕비 단계표는 "12단계 ≈ 94타"를 가정했다. 두 아이의 낱말연습 타수를 먼저 재 보고, 12단계 필요 타수가 언니 타수의 80% 정도가 되도록 `speed`와 `spawnInterval`을 한꺼번에 비례 조정한다.
2. **엄격 모드 대 자유 모드**: 연습에서 틀린 글자를 막는 방식이 답답하게 느껴지는지. 한메처럼 틀린 글자도 들어가고 빨갛게 보이는 방식을 원하면 v0.2에서 짧은 글에만 옵션으로 넣는다.
3. **자동 제출**: 사탕비에서 정확히 맞으면 바로 받는 것이 재미있는지, 아니면 Enter로 "받는" 손맛이 더 좋은지.
4. **★★★ 타수 기준**(낱말 60/70/70, 짧은 글 80)이 10살에게 너무 높거나 낮은지.
5. **자리연습 잠금**: 순서대로 여는 방식이 답답하면 모두 여는 방식으로 바꾼다.
6. **macOS Safari와 한국어 입력기**: 입력 소스가 "한국어 2벌식"일 때 `keydown.code`가 빠짐없이 오는지 집 컴퓨터(브라우저 종류 확인)에서 먼저 확인한다. 특히 Shift+T(ㅆ), Shift+O(ㅒ).
7. **audience 의견 반영됨**: 사탕비, 쿠키 마을, 우산 테마, 사탕을 모아 꾸미기, 완만한 난이도, "내일 또" 실패 화면, 싸움 없는 비교를 반영했다. 남은 확인: 꾸미기 값(30~400)이 너무 비싸거나 싸지 않은지, 하루 한두 판으로 1~2일마다 무언가 하나를 살 수 있는지.
8. **같이 하기(핫시트)**: 이번에는 넣지 않았다. 「우리 집 사탕 병」(12.5)이 협동 역할을 한다. 아이들이 "같이 하고 싶다"고 하면 v0.2 후보로 「번갈아 지키기」를 검토한다. 한 판을 두 명이 단계마다 번갈아 하고, 함께 깬 단계 수를 보여 주는 방식이다.
