**회색 리놀륨 `#B8BEC7` + 중앙 노란 점선 `#FFD34D`**로 통일 — 길찾기의 기준선.

- 친구(구출 대상): 플레이어와 같은 "귀여운 아이" 형태이되 **노랑 테두리 글로우**로 항상 구분.

**아이템**: 실물 재료(비타민, 고추장통, 알람시계, 분필, 큰북, 웃긴 책, 나팔, 물호스)는
**채도 100%에 가까운 원색 + 흰 하이라이트 점 + 은은한 펄스 글로우(스케일 1.0↔1.08, 1.2초 주기)**.
급식표 조각은 10개 전부 **동일한 연노랑 종이 접힌 모양 `#FFF3C4` + 모서리 접힘 그림자**, 반짝임 파티클(흰 별 4개, 랜덤 회전) 고정.

**UI**: HUD 배경은 반투명 남색 `rgba(30,26,58,0.55)` 필 + 흰 텍스트, 버튼은 파스텔 배경에
굵은 흰 테두리. 점수 `+500` 텍스트는 노랑, 시간 보너스는 하늘색, 감점은 없음(감점 텍스트 자체가 없음).

## 2. 캐릭터 디자인 — "빈(bean)" 실루엣, 반지름 13px 기준

Among Us 식 "콩" 몸통: 세로로 조금 긴 캡슐(둥근 사각) + 큰 눈 두 개. 반지름 13px면 화면상
지름 약 26px(뷰포트 스케일 0.8125 적용 시 폰에서 실지름 ~21px) — **디테일 3개 이하로 제한**해야
안 뭉갠다. 우선순위: (1) 몸 색, (2) 눈, (3) 머리 위 아이콘(?/!/zzz). 그 이상은 스케일 죽으면
안 보이니 버린다.

- **플레이어**: 캡슐 몸통(옷색) + 흰 눈 2개(검은 동공, 살짝 위로 향해 생기있게) + 머리 위 짧은
  머리카락 실루엣(4가지 헤어를 몸통 위쪽 곡선 하나로 단순화 — 트윈테일=양쪽 작은 삼각, 단발=일자,
  포니테일=옆으로 흐르는 곡선, 양갈래 번=몸통 위 동그라미 2개). 머리색이 옷색보다 먼저 눈에 들어오면
  안 된다 — **옷색이 실루엣 정체성, 머리색은 보조**.
- **기본 좀비**: 같은 캡슐 실루엣이지만 **팔이 축 늘어져 몸통 밖으로 나와 있음**(플레이어는 팔이
  안 보이거나 짧게 붙어있어 이 차이가 실루엣만으로 구분됨) + 보라 눈 + 눈꺼풀이 반쯤 덮임(눈을 위쪽
  절반만 그려서 졸린 티) + 머리 위 하품 말풍선(작은 회색 타원 "haaa~"). 순찰 중엔 좌우로 느리게
  뒤뚱, 하품 지점에서 몸통이 위로 늘어났다 줄었다(스트레치) 하는 하품 모션.
- **급식 아주머니**: 캡슐이 더 크고 넓적(반지름 16) + 국자 실루엣이 몸 옆으로 튀어나옴(색이 아니라
  형태 차이 — 흑백으로 봐도 구분 가능해야 함, DESIGN.md §4 요구사항 그대로).
- **교장(보스)**: 몸통 폭이 훨씬 크고 정장 각(캡슐보다 어깨가 각진 사다리꼴) + 넥타이 삼각 포인트.
  걸을 때 뒤뚱임 폭이 크고 느려서 "느리다"는 게 형태로도 읽힘.
- **친구**: 플레이어와 동일 실루엣 + 항상 노란 테두리 글로우(펄스) + 눈이 반짝(별 하이라이트 크게).

**4종 헤어·옷 조합이 구분되는 법**: 옷색 4종은 색상환에서 90도씩 떨어뜨려 채도·명도를 통일했으므로
어떤 조합이든 인접 색과 안 헷갈림(코랄/하늘/라임/라벤더). 머리색 4종도 명도 차를 크게 뒀다(검정→금발
순으로 명도 단계). 최악의 조합은 옷과 머리 사이에 항상 **1px 흰 테두리**를 넣어 서로 안 먹힌다.

## 3. `?` vs `!` — 이 게임에서 가장 중요한 시각 신호

DESIGN.md §8 규칙 9를 그대로 스펙화한다.

| | `?` (감지, 유예 0.6초) | `!` (추격 시작) |
|---|---|---|
| 색 | 흰색 `#FFFFFF` + 옅은 회색 테두리 | 빨강 `#FF3B3B` + 흰 테두리 |
| 크기 | 폰트 크기 좀비 반지름의 **1.2배** (작게) | **2.0배** (확실히 큼) |
| 등장 애니메이션 | 위로 8px 부드럽게 떠오르며 페이드인 (ease-out, 0.15초) | 튕겨 나오듯 스케일 0→1.3→1.0 오버슈트 (0.12초, back-ease) |
| 지속 | 0.6초간 고정 표시 후 즉시 `!`로 전환되거나 사라짐 | 추격 지속되는 내내 좀비 머리 위 유지, 매 0.5초 살짝 통통 튐(idle bounce) |
| 화면 반응 | 없음 | 화면 전체 **살짝 진동**(±2px, 0.15초) — 놀이기구 느낌으로 과하지 않게 |
| 사운드 동조 | `notice`(작고 부드러운 "음?")와 등장 프레임 정확히 동기화 | `alert`(짧고 날카로운 2음 상승)와 스케일 오버슈트 프레임 동기화 |
| 배치 | 좀비 머리 정중앙 위 18px | 동일 위치, 크기만 다름 — 위치를 바꾸면 오독 유발되니 위치는 고정 |

추가 제안: `?` 동안 좀비 눈이 살짝 커지면(보라 그대로, 흰자 비율 증가) "봤다"가 표정으로도 이중 전달된다.

## 4. 390px 폭에서 읽기 어려울 것 같은 부분

1. **미니맵 108×72px, 좀비를 점으로 표시(§3 M11)** — 이 크기에서 "방 외곽선 + 느낌표 + 출구 +
   내 위치 + 좀비 점"을 다 넣으면 점 밀도가 높아져 뭉갠다. 미니맵은 **방 블록만 굵은 색 사각형으로
   단순화**하고 세부 벽선은 생략 권장. 아이콘도 재료/출구 2종으로 제한하고 급식표는 미니맵에서 빼는 걸
   추천(어차피 반짝임으로 현장에서 찾게 설계돼 있음).
2. **TILE 40px, 캔버스 스케일 0.8125배 → 폰에서 실질 타일 ~32.5px.** 사물함(`L`)·재료(`V`/`G`) 아이콘이
   이 타일 안에 들어가야 하는데, 재료 아이콘 + 반짝 글로우까지 넣으면 타일 하나를 거의 채운다. 재료
   아이콘은 **타일의 60% 이하** 크기로 그리고 글로우는 아이콘 밖으로 살짝 삐져나오게 해서 "여기 뭔가
   있다"가 캐릭터 크기와 겹치기 전에 보이게 한다.
3. **손전등 콘(70°/260px) + 어둠 오버레이 + 좀비 보라 눈.** 폰 화면에서 어두운 배경 위에 얇은 흰 부채꼴과
   보라 눈이 동시에 있으면, 저채도 화면이라 대비가 낮아질 수 있다. 손전등 콘의 흰색은 살짝 노란기
   (`#FFF3D6`)를 섞어 남보라 배경과의 대비를 확보하고, 좀비 눈은 어둠 속에서 **약한 발광(glow blur)**을
   줘서 손전등 없이도 위치를 어렴풋이 느끼게(§3 M6 "재료는 은은히 반짝" 규칙과 같은 원리를 좀비 눈에도
   살짝 적용 — 완전히 안 보이면 "소리로 찾는다"는 의도가 오히려 좌절로 변할 수 있음, 이건 game-designer
   확인 필요).
4. **우측 하단 버튼 3개(✋88px, ✏️68px, ⏰68px/🔦60px) + 조이스틱** — 그래픽상 문제는 아이콘이 겹쳐
   보이는 것. 지름 60~68px 버튼 안에 이모지+숫자 뱃지(알람 개수)까지 넣으면 이모지가 뭉갤 수 있다.
   이모지 대신 **직접 그린 심플 아이콘(분필 = 짧은 대각선 막대, 알람 = 원+종 두 개)**을 권장 — 이모지는
   기기별 렌더링差도 크다(안드로이드/아이폰 다르게 보임, 색도 못 바꿈). 뱃지 숫자는 버튼 우상단 12px 원.
5. **HUD 재료 아이콘 줄(§5) + 좌상단 미니맵 + 우상단 점수/급식표**가 상단에 다 몰려 있다. 세로
   390×844에서 HUD 상단 60px 안에 이 정보량은 빡빡하다. 미니맵을 살짝 아래(HUD 60px 영역 밖, 게임
   화면 위에 반투명 오버레이)로 내리거나, 재료 줄을 미니맵 옆이 아니라 화면 하단 중앙(Stage 표시 옆)
   으로 옮기는 안을 game-designer와 상의하고 싶다.

## 5. game-designer에게 질문·제안

1. **미니맵에 벽 디테일까지 넣을 계획인지** — 108×72px에서는 방 블록 단위 단순화를 강하게 권한다.
   벽선까지 그리면 스마트폰에서 색 뭉친 회색 사각형 하나로 보일 것.
2. **어두운 방에서 좀비 눈이 손전등 없이 완전히 안 보이는 게 의도인지, 아주 약하게라도 보이게 할지.**
   완전히 안 보이면 "소리로 찾기"가 맞는데, 그러면 청각 의존도가 매우 높아진다. 사운드가 완벽히
   구현되기 전(빌드 초기)에는 이 구간이 "그냥 안 보여서 답답한 방"으로 느껴질 위험이 있다 — 시각적
   완충 장치(아주 옅은 발광)를 기본값으로 넣고 나중에 낮추는 방향 제안.
3. **이모지 버튼(✋✏️⏰🔦⏸)을 실제로 이모지 그대로 쓸 계획인지, 직접 그린 아이콘으로 대체할지.**
   DESIGN.md에 이모지가 스펙 표기로 들어가 있는데, 실제 구현은 캔버스로 그린 아이콘을 강력히 권장한다
   (기기 간 렌더링 불일치 + 색 통일성 문제). 스펙 표기는 그대로 두되 "실제로는 그린다"는 합의만 원함.
4. **교장 보스 반지름이 부록 표에 없다.** 기본 좀비 14 / 아주머니 16처럼 명시가 필요하다.
   "확실히 커야" §4 규칙(실루엣 구분)과 §9(연설 범위 원 크기 대비 균형)를 맞추려면 최소 20~24px을
   제안하고 싶다 — 확정해서 constants.ts 부록 표에 추가해 달라.
5. **친구 구출 시 노란 테두리 글로우와 재료 반짝임(§8 규칙 3)이 같은 노란 계열이라 헷갈릴 수 있다.**
   재료는 정지된 사물에 붙는 반짝임(점멸형), 친구는 캐릭터 테두리 전체 글로우(고리형)로 형태 차이를
   두면 되지만, 색을 아예 다르게 가도 되는지(예: 친구는 하늘색 글로우) 확인하고 싶다 — 노랑은 이미
   손전등 트레이드오프 안내, 교장 연설 범위(§8 규칙 5)에도 쓰이는 톤이라 노랑이 과포화될 우려.
6. **어두운 방(3층)의 "재료·급식표는 은은히 반짝인다"는 규칙과 손전등 콘 조명이 겹치는 자리에서
   시각적으로 뭐가 이길지** — 둘 다 밝은데 손전등 안에서 반짝임이 묻히지 않게, 반짝임에 살짝의 색
   차이(따뜻한 노랑 vs 손전등의 차가운 흰-노랑)를 주고 싶다. 사소하지만 스프라이트 작업 전에 합의해두면
   나중에 다시 안 건드려도 됨.
