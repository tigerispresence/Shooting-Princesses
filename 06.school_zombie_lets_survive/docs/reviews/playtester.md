빌드: BUILD_NOTES.md 2차 갱신 / DESIGN.md v0.3 기준.
테스트 방법: `npm run dev`(포트 3411) + Playwright(Chromium) 자동화.
`window.__zombie`(dev 전용 디버그 훅, `GameCanvas.tsx`)로 상태를 직접 조작해
15구역을 전부 손으로 오래 걷지 않고도 각 메커닉을 검증했다. 키보드(데스크톱)와
`page.touchscreen`/`tap`(아이폰 뷰포트)을 둘 다 사용해 실제 입력 경로를 최대한 그대로 탔다.

이 문서는 테스트를 진행하며 **실시간으로 갱신**된다.

### [보통] 데스크톱 와이드 화면에서 HUD 상단/하단 띠가 게임 캔버스와 정렬되지 않음

- **어디서**: 데스크톱 1280×800, 스테이지 플레이 화면 전체
- **재현 절차**:
  1. 1280×800 데스크톱 뷰포트로 접속
  2. 이름 입력 → 스테이지 1 진입
  3. 상단 점수/급식표/일시정지 줄과 하단 재료 8칸 줄을 확인
- **증상**: 게임 캔버스는 화면 가운데 좁은 박스(약 530×760)로 렌더링되는데,
  상단 띠(`h-[52px]`)와 하단 재료 줄(`h-[40px]`)은 `w-full`이라 뷰포트 **전체 폭(1280px)**으로 늘어난다.
  그 결과 점수(좌상단)·일시정지/음소거(우상단)·재료 8칸(좌하단)·구역 이름(우하단)이
  캔버스에서 한참 떨어진 화면 맨 가장자리에 붙는다. "급식표 n/10"만 우연히 화면 중앙이라
  캔버스 위쪽과 얼추 맞아 보이지만 나머지는 전부 어긋난다.
  DESIGN.md §5 "화면 표시"가 의도한 "정보 3개만 담은 상단 52px 띠"는 캔버스 폭 기준으로
  설계된 것으로 보이는데, 실제로는 페이지 폭 기준이라 넓은 화면에서 눈이 캔버스와
  HUD 사이를 오가야 한다.
- **증거**: `docs/screenshots/05-desktop-stage1-start.png`,
  `docs/screenshots/05b-top-strip.png`(상단 크롭), `docs/screenshots/05c-bottom-strip.png`(하단 크롭)
- **심각도**: 보통 — 플레이는 막히지 않지만 데스크톱에서 의도한 레이아웃과 다르고 가독성이 떨어짐.
  **아이폰 390px 세로에서는 캔버스가 화면 폭을 거의 채우므로 이 문제가 나타나지 않음을 확인**
  (`docs/screenshots/24-iphone-stage1-play.png` 참고 — 아이폰에서는 상단/하단 띠가 캔버스와 잘 맞음).

### [사소] 정지 화면 클리어 후 `friendsMet`가 `boolean[]`이어야 하는데 `false`가 `null`로 저장됨

- **어디서**: 전체 흐름 — 스테이지 1/2/3/5처럼 **그 판에 구출 가능한 친구가 없는 스테이지**를 클리어할 때마다
- **재현 절차**:
  1. 새 프로필로 스테이지 1을 클리어
  2. `localStorage`의 `zombie-school:v1` → `friendsMet` 값을 확인
- **증상**: `App.tsx`의 `handleClear`가
  `next.friendsMet = data.friendsMet.map((v, i) => v || r.friendsMet[i])`로 병합하는데,
  `ClearResult.friendsMet`(`GameCanvas.tsx`)는 `s.friends.map(f => f.state === "follow")`로 만들어진다.
  스테이지 1/2/3/5의 맵에는 구출 가능한 친구(`F`)가 아예 없어 `s.friends`가 **빈 배열**이고,
  따라서 `r.friendsMet[i]`는 4칸 전부 `undefined`다. `false || undefined`는 `undefined`가 되고,
  이게 JSON으로 저장되며 `null`로 직렬화된다. 즉 **스테이지 4 이전에 어떤 스테이지든 한 번만 깨도
  아직 못 구한 친구 칸이 전부 `false`에서 `null`로 바뀐다.** 실측: 스테이지 1 클리어 직후
  `friendsMet: [null,null,null,null]`.
- **영향**: `EndingScreen.tsx`와 `StageSelect`는 전부 `if (friendsMet[i])` / `.filter(Boolean)`처럼
  참·거짓만 따지므로 **현재는 화면에 보이는 증상이 없다** (null도 false와 동일하게 "안 만남"으로 처리됨).
  다만 타입 선언(`boolean[]`)과 실제 저장값이 어긋나 있어, 나중에 `friendsMet[i] === false`처럼
  엄격 비교를 쓰는 코드가 추가되면 조용히 깨질 수 있다.
- **증거**: 02-stage1-clear-persist.js 실행 로그 —
  `RESULT: localStorage-after-clear= {...,"friendsMet":[null,null,null,null],...}`
- **심각도**: 사소 — 지금 당장 눈에 보이는 버그는 아니고, 데이터 정합성 문제.

## 확인된 정상 동작

### 1. 데스크톱 플로우
- 타이틀 → "시작하기" → 이름 입력 화면 정상 진입. 콘솔 오류 없음.
- 이름 입력: 빈 이름이면 "이걸로 할래!" 버튼이 `disabled` 유지 (정상).
- 이름 입력: 정상 이름("하린") 입력 시 버튼 활성화 (정상).
- 이름 입력: `maxLength=6` 강제 — 9자("가나다라마바사아자")를 넣어도 input value가 "가나다라마바"(6자)로 잘림.
- 외모 선택(머리색/옷색 스와치) 렌더링 정상, 스테이지 선택 화면 진입 정상.
- 스테이지 선택: 스테이지 1만 해금, 2~5는 `disabled`로 잠김 표시.
- 스테이지 1 진입: 미니맵 오버레이, HUD, 구역 카드("1-1 현관 → 복도"), 무전 대사
  ("하린아, 다들 좀 이상해. 조심해!") 정상 표시.
- 재료 2개 획득 + 출구 오픈 + 출구 타일 진입 → `stageClear` 정상 동작 (엔진 로직 `exitOpen`/`finishStage` 경유 확인).
- 스테이지 클리어 화면: 별 개수, 항목별 점수(재료/급식표/클리어/시간보너스/들키지 않았어!/쌩쌩해요!), 합계 정상.
- `localStorage` 저장: `unlockedStage: 2`, `stars: [1,0,0,0,0]`, `best: [4794,0,0,0,0]` 정상 기록.
- 새로고침 후 "이어하기" → 스테이지 1 별점(★☆☆)·최고점수 유지 + **스테이지 2 잠금 해제** 확인. 진행도 영구 저장 정상.

### 3. 게임오버 → 컷신 → 스킵 → 재시작
- 좀비와 충돌 시 `phase: "sleeping"` 정상 전환 (엔진 `caught()` 경유, `CATCH_DIST` 판정 확인).
- 컷신 진행 중 "딩동댕동~" → "아 깜짝이야! 얼마나 잤지?" 등 문구 정상 표시, 화면 톤 다운 확인.
- 0.4초(SKIP_AFTER_MS) 이후 탭/클릭 시 `skipCutscene()`으로 `sleepT`가 즉시 `GAMEOVER_MS`(3000)까지 점프,
  "종 치고 다시!" 버튼 등장 확인.
- "종 치고 다시!" 클릭 → `phase: "playing"` 복귀까지 **약 60ms 이내**(측정에 포함된 인위적 대기 포함치이므로
  실제로는 이보다 짧음) — DESIGN.md §6의 300ms 예산 안. BUILD_NOTES가 주장한 "17ms"와 오더가 일치.
- 재시작 후 카메라·구역(체크포인트)이 정확히 잡혀 있던 자리(예: "1-2 보건실")로 복귀 확인 —
  스테이지 처음이 아니라 **구역 시작점**으로 재개 (스펙 §6 그대로).
- 재시작 전에 주운 재료(`item.taken` + `s.gotIngredients[i]`)가 재시작 후에도 그대로 유지됨을
  `restartFromCheckpoint()`가 items/gotIngredients를 건드리지 않는 것으로 코드 레벨까지 확인.
- 재시작 전후로 배경/캐릭터 색감이 달라 보이는 현상을 발견해 별도로 재검증했으나,
  이는 렌더링 버그가 아니라 **체크포인트 지점(구역 시작점)의 카메라 위치가 잡혀 캐릭터가 처음 보던
  각도와 다른 부분을 비추는 것**뿐이었다(같은 지점을 baseline과 재대조해 색상이 100% 동일함을 확인).
- 스크린샷: `docs/screenshots/09~11`(최초 발견), `12~15`(재검증, baseline과 재시작 후 동일 화면 비교).

### 4. 스테이지 1~5 메커닉 스모크 테스트
- **스테이지 2 — B-1 아주머니 대기(dormant)**: 스테이지 진입 시 아주머니는 복도 오른쪽 끝(`x=1260,y=380`)에서
  `dormant:true`로 정지. 분필(`C`, 재료 인덱스 2)을 실제 상호작용 키(`E`)로 주운 순간 `dormant:false`로
  전환되고 1초 뒤 좌측으로 실제 이동 시작(`x:1260→1223`)까지 확인. BUILD_NOTES B-1 항목 그대로 동작.
- **스테이지 2 — 급식 아주머니 화면 밖 빨간 화살표**: 아주머니로부터 300px 떨어진 지점(화면 밖, 미니맵 반경
  320px 이내)에 플레이어를 두자 화면 오른쪽 가장자리에 흰 테두리의 빨간 삼각 화살표가 정확히 렌더링됨
  (`docs/screenshots/35-stage2-matron-arrow.png`).
- **스테이지 3 — 어두운 방 + 손전등**: 미술실(3-2) 진입 시 어두운 남보라 오버레이 + 부드러운 시야원(150px)
  확인. `F` 키로 손전등 on 시 `#FFF3D6` 계열의 부채꼴 빛이 정확히 표시되고, 최초 점등 시 무전
  "손전등 켜면 잘 보여. 근데... 더 잘 들켜." 정상 표시(스펙 문구와 일치).

- **스테이지 3 — 알람시계**: `Q`로 설치 → 배치 직후 `ringing:false` → 약 1초(`ALARM_DELAY=1000`) 뒤

- **스테이지 4 — 렌더 스케일 0.8 줌아웃**: `s.stage.renderScale === 0.8` 확인, 좀비 10마리/친구 4명 전부 로드됨.
- **스테이지 4 — 친구 구출/미끼 메커닉**: 연습 모드(좀비 0마리)에서 친구를 1초간 상호작용(`E`)으로 깨우자
  `state: "asleep" → "follow"`, 점수 `+700`(SCORE.friend) 정상 지급, 이후 플레이어를 움직이자 친구가
  하늘색 글로우 링을 두르고 뒤따라옴 확인(`44-...`, `45-...`).
  **부가 확인(의도된 동작)**: 실제 좀비가 있는 상태에서 같은 자리에 가만히 서서 친구를 깨우면, 깨우기
  완료 직후 근처에서 추격해 온 좀비가 22px 이내로 붙어 있어 **친구가 그 자리에서 다시 잠들고
  좀비가 2초간 하품하며 멈추는 "미끼" 메커닉이 정확히 재현됨** (`FRIEND_STALL_MS=2000` 부여 확인).
  DESIGN.md §M7 "이득 1 — 미끼"와 일치하는 정상 동작이며 버그 아님.
- **스테이지 5 — 보스 사이클**: `walk(~5.5s) → windup(~1.0s) → speech(radius 0→200, ~0.8s에 걸쳐 확장,

- **스테이지 5 — 방송 게이지**: 해독제 없이(`exitOpen:false`) 방송실 문에서 상호작용해도 게이지가

  누르고 있는 동안 0→500→999→3000까지 정확히 누적되고 3000 도달 시 `phase:"stageClear"`로 전환
  확인(`54-broadcast-clean-progress.png`, `55-broadcast-clean-cleared.png`). 화면 하단에 "방송 준비 n%"

- **엔딩 화면**: 스테이지 5 클리어 후 "다음 스테이지" 클릭 → `EndingScreen` 진입, 구출한 친구(3/4)만
  플레이어 옆에 하늘색 글로우로 등장하고 못 구한 친구 자리는 비어 있음을 확인(`60-ending-screen.png`).

#### [막힘] 환풍구를 실제 사람 입력으로는 "발견"할 수 없다 — `held`와 `pressed`가 같은 프레임에 같이 켜져서 발견 분기가 통째로 막힘

  둘 다 재현됨.
- **재현 절차**:
  1. 스테이지 1, 급식실 배식구 뒤 환풍구 그릴(11,7) 위에 선다.
  2. 손 버튼을 **보통 사람이 누르는 속도로**(약 80~150ms) 눌렀다 뗀다.
  3. `window.__zombie.current.foundVents[0]`을 확인한다 — `false`인 채로 남는다.
  4. 아무리 다시 눌러도(짧게, 길게, 여러 번) 안 된다. 오직 "누르는 순간과 떼는 순간이 같은
     애니메이션 프레임 안(16ms 미만)"일 때만 `true`가 된다 — 사람 손가락으로는 사실상 불가능하다.
- **원인** (`src/app/game/engine.ts` `updateInteraction()`): `pressInteract()`가 `held=true`와
  `pressed=true`를 **동시에** 켠다. `updateInteraction`은 `if (t && s.held)` 분기를 **먼저** 보는데,
  `t.kind === "vent"`면 `v.found`가 `false`라도 그 안에서 아무 것도 안 하고 **무조건 `return`**한다.
  `pressed`를 소비하는 "누르면 발견한다" `switch` 문(`case "vent": if (!v.found) findVent(s, v)`)은
  이 `return` **뒤**에 있어서 절대 도달하지 못한다. `pressed`는 `update()` 끝에서 프레임마다 무조건
  `false`로 리셋되므로(사물함/문/아이템 등 다른 상호작용은 이 문제가 없다 — `held` 분기에
  `vent`만 걸려 있다), 실제로 버튼을 누르고 있는 한 프레임이라도 지나가면 그 프레스에서는
  다시는 발견 기회가 없다. 사람의 탭은 예외 없이 1프레임(16.7ms)보다 길다.
- **영향**: V1 환풍구 기능 전체의 진입점이 실사용 환경(터치·키보드·마우스 전부)에서 막혀 있다.
  아이가 그릴을 찾아 눌러도 "비밀 통로!" 연출이 절대 뜨지 않는다. `held/found` 이후 단계
  (0.8초 꾹 눌러 진입, 추격 차단, 크롤, 저장)는 전부 정상 동작하지만, **그 앞의 문을 열 방법이 없다.**
- **증거**:
  - `docs/screenshots/pt2-02-standing-on-vent-undiscovered.png` (그릴 위, 아직 하이라이트 없음 — 정상)
  - `docs/screenshots/pt2-03-after-realistic-tap-still-undiscovered.png` (~120ms 정상 탭 후에도
    `환풍구` HUD 카운터가 안 보임 = 발견 안 됨)
  - 실측 로그: `STEP realistic ~120ms tap to discover vent -> found0 should become true:
    {"found0":false,"score":0}` vs 같은 자바스크립트 틱 안에서 내리고 뗀 경우만
    `{"heldRightAfterDown":true,"pressedRightAfterDown":true,"heldAfterUp":false,"pressedAfterUp":true}`
    → `found0=true`.
- **심각도**: 막힘 — 게임 전체가 막히지는 않지만, **환풍구 기능 자체가 실사용 환경에서 100% 진입
  불가**라 이 기능만 놓고 보면 블로커. `held`와 `pressed`를 동시에 켜는 대신, vent 분기를
  "발견 전(`!v.found`)이면 `pressed` 소비 로직까지 흘러가게" 고치거나, `pressInteract()`에서
  `pressed`를 한 프레임 늦게(또는 `releaseInteract()`에서) 세팅하는 식으로 고쳐야 한다.

  폭이 세로 기준 ~390으로 고정돼 있어서 실제 화면 폭과 무관하게 똑같이 잘림).
- **재현 절차**:
  1. `friendsMet: [true,true,true,true]`로 스테이지 5에 입장한다(스테이지 4를 4명 다 구출하고 클리어).
  2. 동행 친구 아이콘 4개가 하단 재료 줄 오른쪽에 표시된다.
  3. "구역 이름"(예: `5-1 과학실`) 텍스트의 위치를 DOM에서 재본다.
- **증상**: 동행이 0명일 때는 라벨이 `width 52px, right 378px`로 390px 화면 안에 정상 표시된다.
  동행이 4명이 되면 같은 라벨이 `width 12.8px, height 90px, left 392px`로 바뀐다 — 글자 하나하나가
  세로로 줄바꿈되면서 폭이 거의 0으로 눌리고, 그마저도 **390px 화면 오른쪽 바깥(392px~)으로
  완전히 밀려나 안 보인다.** `justify-between` 한 줄에 [재료 8칸] + [동행 아이콘 4개] + [구역 이름]을
  다 욱여넣으면서 라벨에 `white-space: nowrap`이나 최소 폭 보장이 없어서 생기는 문제로 보인다.
  스테이지 5는 다섯 스테이지 중 마지막이고, 친구를 다 구하는 게 권장되는 정상 플레이 경로라
  **흔히 발생하는 상황**이다.
- **증거**:
  - `docs/screenshots/pt2-72-section-label-offscreen-with-4-companions.png` (라벨이 아예 안 보임 —
    바로 위 `pt2-24`/`pt2-70` 스테이지5 스크린샷들과 비교해도 하단 우측에 텍스트가 없다)
  - 실측: 동행 0명 `{"sectionText":"5-1 과학실","elRect":{"width":52.09,"left":325.9,"right":378}}`
    vs 동행 4명 `{"sectionText":"5-1 과학실","elRect":{"width":12.83,"height":90,"left":392}}`
- **심각도**: 심각 — 플레이는 막히지 않지만(구역 이름은 정보성 텍스트) 게임의 마지막 스테이지에서,
  구출을 다 해낸 보상 상태일 때 오히려 HUD 요소 하나가 통째로 사라진다.

  시야를 잃고 `investigate`로 자주 풀리는 바람에 같은 테스트를 반복 재현하는 게 타이밍에 민감했다 —
