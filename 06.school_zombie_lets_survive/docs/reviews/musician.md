# musician 리뷰 — 사운드 기획 v0.1

STORY.md / DESIGN.md 승인 내용 기준. 코드는 아직 안 씀 — `game-builder`가 뼈대를 만든 뒤
`audio.ts`/`music.ts`를 붙인다. `04.escape_room`의 스텝시퀀서 구조(25ms 폴링, 32스텝 루프,
리드/베이스/아르페지오 3성부)를 그대로 물려받을 생각.

톤 원칙: **좀비는 안 무섭다, 졸릴 뿐이다.** 미묘하게 낮은 음, 몽글몽글한 필터는 써도
단조 화성단음계(무서운 옥타브 도약, 트라이톤)는 쓰지 않는다. `escape_room`의 지하감옥 곡 같은
"으스스함"은 이 게임엔 없다.

## 3. 포지셔널 오디오 — 좀비 하품

- **좌우**: `StereoPannerNode.pan = clamp((zombieX - playerX) / 240, -1, 1)`. 240px는 대략
  화면 폭(480 논리 px)의 절반 — 화면 가장자리에 있으면 완전히 한쪽으로 쏠리게.
- **거리 볼륨**: 청취 반경 **260px** (미니맵 표시 반경 250px보다 살짝 넓게 잡아서 소리가
  미니맵 점보다 한 박자 먼저 들리게 — "어? 뭔가 있다"의 예감을 준다).
  `gain = max(0, 1 - dist/260)^1.5` (선형보다 급하게 죽여서 가까운 애만 또렷하게 들림).
- **벽 감쇠(제안)**: 시야(LOS) 판정과 별개로, 하품 소리는 벽이 있어도 **완전히 막지 않고
  먹먹하게**(로우패스 1500Hz + 볼륨 ×0.5) 통과시킨다. "안 보이지만 벽 너머에 있는 걸
  희미하게 느낀다"는 게 사물함 숨기/문 잠그기와 궁합이 좋다 — 숨어서 밖의 하품 소리로
  나갈 타이밍을 잰다(§DESIGN M2에서 말한 "틈으로 보는" 재미의 청각 버전).
- **세로 방향은 표현이 안 된다**: 위/아래 거리는 팬에 안 잡히고 볼륨에만 녹아서, 좀비가
  바로 위에 있는지 바로 아래에 있는지는 소리만으론 구분 불가. → **아이 혼자 소리만으로
  정확한 좌표를 찾기엔 부족**하다. 좌우 대략 방향 + "가까워졌다/멀어졌다" 느낌 정도가
  한계이고, 정확한 위치는 결국 미니맵 점(250px 이내)과 화면 안 좀비 실루엣이 맡는다.
  → 오디오는 **예고편**, 확정 정보는 항상 시각. 이 역할 분담을 설계자에게도 명시 필요(§5).

## 4. "졸음 모티프" (재사용 4음구)

**솔-미-도-라** (A단조 5음계 기준, 실제 음: G4-E4-C4-A3, 순서대로 내려가며 하품하듯 늘어짐).
음마다 다음 음으로 **포르타멘토(글리산도) 슬라이드**를 걸어 "노래한다"기보다 "늘어진다"는
인상을 준다. 등장하는 세 곳에서 속도/음역만 바꿔 같은 모티프임을 들키게 한다:

1. **`notice`/`?` 연출**: 모티프를 8배속으로 압축(전체 150ms), 높은 옥타브(G5-E5-C5-A4) —
   "어? 저거…" 하고 순간적으로 스친다.
2. **`sleep` 게임오버**: 원래 속도(전체 1.6초), 중간 옥타브, 마지막 음(A3)에서 volume이
   꺼지듯 페이드 — 진짜로 잠드는 느낌.
3. **보스 연설(`bossSpeechLoop`) 도입부 1음절**: 한 옥타브 낮춰(G3-E3-C3-A2) 포먼트
   필터를 통과시켜 "저음으로 웅얼거리는 교장 선생님" 버전 — 아이들이 "어? 그 소리다"
   하고 알아채는 지점.

세 번 다 듣고 나면 아이가 "이 소리 = 졸림"이라는 걸 학습하게 되는 게 목표. 타이틀 BGM
인트로 두 마디에도 이 모티프를 원곡 조성(C장조: E-C-G-E쯤으로 이조)으로 슬쩍 심어서
"이 게임의 테마"라는 걸 처음부터 깐다.

## 5. game-designer에게 확인하고 싶은 것

1. **`bossCough`(회복 신호)가 사실상 오디오 전용 정보다.** DESIGN.md 자체가 "소리만
   듣고도 지금이 기회인 걸 알아야 한다"고 적어놨는데, 무음/무음스위치 폰에서는 이 신호가
   통째로 사라진다. → 회복 구간에 **시각적으로도 확실한 변화**(예: 교장이 헛기침하며
   허리를 펴는 동작 + 머리 위 아이콘이 노란 링에서 편안한 초록 점으로 바뀜)가 반드시
   있어야 한다고 본다. graphic-designer/game-designer 확인 요청.
2. **급식 아주머니는 시각적으로만 구분되고(§8-4) 소리로는 구분이 없다.** 순찰이 빠르고
   경로가 고정이라 화면 밖에서 접근할 때 대비가 늦을 수 있어 `matronClank`(국자 소리,
   더 크고 명확한 금속음)를 제안했다. 미니맵 250px 반경 안에서만 보이는데, 아주머니
   속도(104px/s)면 250px를 2.4초에 주파한다 — 소리를 꺼둔 아이에게 이게 너무 촉박한
   경고 시간이 아닐지 확인 부탁한다. (미니맵 반경을 아주머니 한정 300px로 늘리는 안도
   검토 가능.)
3. **`broadcastTick`(방송 게이지 채우는 소리)은 온전히 보너스여야 한다.** 게이지 자체가
   "화면 하단 큰 바"로 이미 표시되므로 소리를 꺼도 진행 상황을 알 수 있다 — 이 전제가
   맞는지, 즉 게이지 UI가 정말 항상 화면에 크게 떠 있는지 재확인.
4. **뮤트 스위치를 켠 아이도 스테이지 1~5를 클리어할 수 있어야 한다는 전제로 설계했다.**
   즉 하품 소리, 보스 헛기침, 알람/분필 소리 전부 "있으면 더 편하고 없어도 깨지지 않는"
   보조 정보로 잡았다. 이 전제에 동의하는지, 아니면 특정 구간(예: 도서관 3-3의 "여러
   마리 동시 반응")만큼은 청각 정보가 필수여도 괜찮다고 볼지 결정이 필요하다.
5. **BGM 볼륨 vs SFX 볼륨을 별도로 끌 수 있게 할지.** `escape_room`처럼 bgmBus/sfxBus를
   나눠서, "음악은 끄고 효과음(하품 등 정보성 소리)은 켜기"를 지원하는 편이 사운드가
   게임플레이 정보를 나르는 이 게임에 더 맞다고 본다. HUD에 뮤트 토글이 음악/효과 둘로
   나뉘는 걸 원하는지, 아니면 하나로 통합해도 되는지 확인 요청.
6. **`nearMiss` 사운드가 화면 흰 섬광(0.2초)과 겹치는데, 추격 중(빠른 심장박동 느낌 BGM)
   위에 얹히면 놀랄 수 있다.** 부드러운 "쉬익"으로 설계했지만 실제 빌드 후 playtester가
   "추격 중에 갑자기 튀는 소리 아닌지" 확인해줬으면 한다.

`audio.ts`(엔진 + unlock) → `music.ts`(스테이지별 시퀀서) 순으로 붙이겠다. 실제 코드는
그 시점에 작성.
