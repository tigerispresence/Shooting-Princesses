## 0. 가장 먼저 — 이동 방식 결정

### 결론: **자유 8방향 이동** (칸 단위 이동 아님)

`04.escape_room`은 15×11 / TILE 40 / `MOVE_MS = 145`의 **칸 단위 스텝 이동**을 쓴다.
이 게임은 그 방식을 **쓰지 않는다**. 격자(타일 맵 + ASCII 레벨 데이터)는 그대로 물려받되,
플레이어와 좀비는 **float 픽셀 좌표 + 원형 충돌체**로 움직인다.

이유 (빌더가 나중에 뒤집지 않도록 명시):

1. **스텝 이동은 추격에서 반응을 막는다.** `escape_room`은 한 번 스텝을 시작하면 145ms 동안
   입력이 잠긴다(`p.moveAt` 해제 전까지 `tryStep` 호출 안 됨). 퍼즐 게임에서는 문제없지만,
   좀비가 다가올 때 145ms 입력 잠금은 "못 피했다"가 아니라 "조작이 안 먹었다"가 된다.
   아이가 억울해하는 실패는 재시도 의욕을 깎는다.
2. **Among Us 느낌의 핵심은 비껴 지나가기다.** 복도에서 좀비 옆을 스치듯 통과하는 맛은
   반 칸 단위 위치가 있어야 나온다. 칸 단위면 "같은 칸이냐 아니냐"의 이진 판정뿐이다.
3. **대각선 이동이 공짜로 생긴다.** 아이들은 조이스틱을 대각선으로 민다. 8방향이 자연스럽다.
4. **감지 반경·소리 반경·연설 범위가 전부 원형(px)이다.** 칸 단위와 섞으면 판정이 어색해진다.

### 그래도 격자는 쓴다

- 맵은 ASCII 문자열 배열 (`escape_room`의 `rooms.ts` 방식). 손으로 편집 가능해야 한다.
- 충돌은 **원 vs 타일 AABB**. 축별로 분리해서 처리한다(먼저 x 이동 → 막히면 x만 되돌림 → 그다음 y).
  이래야 벽에 대각선으로 비벼도 안 끼고 벽을 따라 미끄러진다. **벽 끼임은 이 게임 최대의 적이다.**
- 코너 보정: 이동 방향으로 막혔는데 옆으로 12px 이내에 빈 공간이 있으면 자동으로 밀어준다.

## 3. mechanics[]

### M1. 졸음 좀비 (기본 적)

| 상태 | 행동 |
|---|---|
| 순찰 (patrol) | 지정된 웨이포인트 루프를 걷는다. 각 지점에서 0.8~1.6초 멈춰 하품 |
| 감지 (notice) | 플레이어가 감지 반경 안 + **벽에 가리지 않음**(직선 시야) → 머리 위 `?` |
| 추격 (chase) | `?` 시간이 끝나면 `!` 표시 + 추격. 속도 상승 |
| 포기 (giveup) | 시야에서 벗어나 일정 시간이 지나면 마지막으로 본 지점까지 간 뒤 하품하고 순찰 복귀 |

- **`?` 유예(0.5~0.6초)가 이 게임의 공정성이다.** 들켜도 즉사가 아니라 "어? 지금 뛰면 된다"가 있다.
  실패가 항상 내 판단 탓으로 느껴져야 한다.
- 시야 판정은 **원 + 직선 LOS**. 시야 콘(부채꼴)은 쓰지 않는다 — 10살에게 적이 바라보는 방향을
  읽으라는 건 요구가 너무 많다. 대신 좀비는 **하품 소리 + 보라 눈 + 머리 위 하품 말풍선**으로 위치를 알린다.
- 잡힘 판정: 중심 거리 **20px 미만** (반지름 합 27보다 작게 = 제대로 겹쳐야 잡힌다).

#### M1-b. 「배고픈 좀비」 — 스테이지 1-3에서만 (신규, v0.2)

- 급식실을 도는 **딱 1마리**. 순찰 **52 px/s**, 추격 **88 px/s**, 감지 **110px**, `?` 유예 0.6초.
- 플레이어(130)와의 속도 차가 1.76배 → **1.48배**로 좁혀진다.
  직선으로는 여전히 도망칠 수 있지만 **급식 테이블을 끼고 도는 순간 따라잡힌다** →
  아이가 처음으로 "아, 이건 숨어야겠다"고 생각하게 만드는 장치.
- 순찰 경로가 급식 테이블(`T`) 뒤를 지나서 **시야가 막힌 채로 갑자기 등장**한다.
  **이 경로만은 자동 생성이 아니라 손으로 찍는다** — "테이블 뒤에서 튀어나온다"가 이 좀비의 존재 이유다.
- 겉모습: 기본 좀비와 같되 **급식판을 들고 있고 뒤뚱거림이 눈에 띄게 빠르다**.
  나중에 나올 급식 아주머니의 예고편 역할 (graphic-designer §2의 "형태로 구분" 원칙 적용).
- 스테이지 1의 나머지 규칙(사물함 9개, 타이머 없음, 목숨 없음)은 그대로 — **여전히 거의 질 수 없다.**

### M2. 사물함 숨기

- 사물함 타일에 34px 안으로 붙어 상호작용 → 0.25초 문 닫는 연출 → **완전 무적, 감지 불가**.
- 나오기도 같은 버튼. 나오는 데 0.25초.
- **숨어 있는 시간 제한 없음.** (기다리게 해서 벌주지 않는다)
- 들어가는 걸 본 좀비는 사물함 앞에서 3.5초 하품하다 순찰로 돌아간다 → 숨기는 **시간 비용**만 든다.
- 재진입 쿨다운 **1.2초** (같은 사물함). 문 여닫이 연타로 화면이 깜빡이는 걸 막는 용도.
- 사물함 안에서는 **살짝 열린 틈**으로 밖이 그대로 보인다 (가장자리에 나무결 프레임).
  나갈 타이밍을 직접 재는 게 이 메커닉의 재미다.
- BGM에 로우패스 1200Hz만 살짝 걸어 "문틈으로 듣는" 느낌 (musician §1). **곡은 바꾸지 않는다** —
  1.2초마다 곡이 바뀌면 어지럽다.

### M3. 분필 던지기 (스테이지 2에서 습득)

- 속도 **240 px/s**, 최대 사거리 **200px**, 벽에 맞으면 그 자리에 떨어짐.
- 착지 시 **소리 반경 130px**: 그 안의 좀비가 착지 지점으로 이동해 **2.5초** 두리번거림.
- **쿨다운 1.2초, 개수 무한.** 소모품으로 만들면 아이가 다 써버리고 막힌다. 절대 막히면 안 된다.
- 이미 추격 중인 좀비도 분필에 반응한다(추격 해제). 이게 "역전 카드"라 던질 맛이 난다.

### M4. 알람시계 (스테이지 3부터 사용)

- 발밑에 놓음 → **1.0초 후 울림 시작 → 4.0초 지속**.
- 소리 반경 **220px**, 그 안의 좀비 전원을 시계 쪽으로 끌고 와 **울리는 내내 붙잡아 둔다**.
- 소지 최대 **3개**. 스테이지 시작 시 2개 보장, 맵에 1~2개 배치.
- 분필이 "잠깐 돌린다"면 알람시계는 "구역을 통째로 비운다".

### M5. 문 잠그기 (스테이지 2부터)

- 교실 문에 상호작용 → **0.6초 잠금 동작** → 그 문은 **8초간** 좀비가 못 지나감.
- 좀비는 잠긴 문을 두드리다 다른 길로 돌아간다.
- 한 문은 판당 3번까지. 남은 횟수가 문에 점 3개로 표시된다.

### M6. 어두운 방 + 손전등 (스테이지 3부터)

- 어두운 방은 어둠 오버레이. 기본 시야 원 **반경 150px**(부드러운 가장자리).
  **검정(`#000`)을 쓰지 않는다 — 짙은 남보라 계열만.**
- 손전등 ON → 바라보는 방향 **각도 70° / 사거리 260px** 콘. 색은 순백이 아니라 **`#FFF3D6`**
  (남보라 배경과의 대비 확보, graphic-designer §4-3).
- **트레이드오프**: 손전등을 켜면 좀비 감지 반경이 **×1.35**. "밝게 보고 싶다 vs 안 들키고 싶다".
  처음 켜는 순간 무전 한 줄로 알려준다 — `"손전등 켜면 잘 보여. 근데... 더 잘 들켜."`
- **어둠 속에서도 보이는 것** (막혀서 좌절하지 않게):
  - 재료·급식표 → **따뜻한 노란 반짝임** (손전등의 차가운 흰노랑과 색으로 구분)
  - **좀비 눈 → 반경 26px의 약한 보라 발광** (v0.2 신규, graphic-designer §5-2).
    벽 너머로는 보이지 않는다. "완전히 안 보이는 방"은 도전이 아니라 짜증이다.
- **어둠 오버레이는 플레이어가 그 방 "안"에 있을 때만 켠다.** 복도에서 들여다보면 어두운 바닥색은
  보인다. 다만 **어두운 방 안의 좀비·재료·급식표·친구는 밖에서 그리지 않는다** —
  밖에서 미리 정찰해 버리면 어둠이라는 메커닉이 통째로 무력해진다. 미니맵 점(250/320px)은 그대로 보인다.
- 3-2 첫 진입 시 무전: `"깜깜해도 괜찮아, 손전등 있잖아!"`

### M7. 친구 구출 — **페널티 없음** (v0.2 전면 개정)

- 숨어 있는 친구에게 상호작용 → 따라온다 (플레이어 뒤 32px를 부드럽게 추적, 여러 명이면 줄줄이).
- **이득 1 — 미끼**: 추격 중인 좀비는 **플레이어와 친구들 중 가장 가까운 대상**을 쫓는다.
  좀비가 친구에게 닿으면 친구가 그 자리에서 잠들고, **좀비는 2.0초간 옆에서 같이 하품하며 멈춘다.**
  친구는 방패이자 시간 벌이다.
- **이득 2 — 점수**: 1명당 **+700**, 스테이지 끝에 4명 전원이 깨어 있으면 별 3개 조건.
- **비용**: 잠든 친구를 다시 깨우러 가는 시간(상호작용 **1.0초**). 그게 전부다.
- **감지 반경 페널티는 완전히 삭제했다.** (v0.1의 +20%)
  이유: 구출이 조금이라도 손해로 읽히면 아이는 안 한다. 친구 구출은 **언제나 순이득**이어야 한다.
- 친구가 잡히는 순간 대사로 웃기고 넘어간다 — `"내가 너무 시끄러웠나 봐... 미안!"` (story-builder §4-5)
- **친구 때문에 게임오버가 되는 일은 없다.**

친구 4명 (프로필 정본: `reviews/story-builder.md` §3): 하늘 / 다온 / 준호 / 세은.
전원 스테이지 4에 고정 배치 — **4-2에 하늘·다온, 4-3에 준호·세은.**
세은(방송부)을 마지막에 구하면 스테이지 5 방송실로 자연스럽게 이어진다.

### M8. 급식실 아주머니 좀비 (스테이지 2부터)

- 국자를 들고 **정해진 경로를 빠르게** 왕복. 두리번거림 없이 쭉 간다.
- 빠르고 감지 반경도 넓지만 **경로가 완전히 고정**이라 외울 수 있다.
- 분필 반응 시간이 짧다(1.2초). 알람시계에는 정상 반응.
- **화면 밖에서 오는 걸 반드시 미리 알 수 있어야 한다** (musician §5-2 — 104 px/s면 250px를 2.4초에 주파):
  - 미니맵 표시 반경 **320px** (일반 좀비 250px보다 넓게) + **빨간 사각형**으로 표시 (일반은 보라 점)
  - 화면 밖 320px 이내면 **화면 가장자리에 빨간 화살표**
  - `matronClank` (국자 금속음) 0.3초 간격 반복

### M9. 교장 선생님 보스 (스테이지 5) — **사이클 단축** (v0.2)

| 단계 | v0.1 | **v0.2** | 내용 |
|---|---|---|---|
| 걷기 | 9.0초 | **5.5초** | 플레이어 쪽으로 **34 px/s**(v0.1 26). 닿으면 잡힘(거리 28px) |
| 예고 | 1.2초 | **1.0초** | 마이크를 든다. 발밑 노란 링 깜빡. "에—" |
| 연설 | 4.0초 | **3.5초** | 졸음 반경 0 → **200px로 0.8초에 걸쳐 확장** 후 유지. 안에 있으면 잡힘 |
| 회복 | 2.5초 | **2.2초** | 헛기침. 완전 무해, 이동 13 px/s |
| **총 사이클** | 16.7초 | **12.2초** | 안전 구간 7.7초 (63%) |

이동 속도를 26 → 34로 올린 건 걷기 구간이 짧아져 압박이 사라지는 걸 보정하기 위함이다.
그래도 플레이어(130)의 **1/3.8** — 달리기로는 절대 안 잡힌다.

핵심 규칙 3가지 (전부 화면으로 읽혀야 한다):
1. **연설 중엔 눈을 감고 있다** → 몸통 충돌이 꺼진다. **그냥 통과해서 지나갈 수 있다.**
2. **연설은 벽·기둥에 막힌다.** 기둥 뒤에 있으면 반경 안이어도 안전. 복도에 기둥 3개.
3. 안전 창 = 회복 2.2초 + 걷기 5.5초. **회복 시작 신호는 소리(`bossCough`)와 그림(§9-0) 양쪽으로 온다.**

보스전 목표: **해독제를 든 상태로** 방송실 문 앞에서 **상호작용을 총 3.0초 누적** → 방송 ON.
(해독제가 없으면 게이지 자체가 차지 않는다 — 5-1을 건너뛸 수 없게 하는 잠금)
진행 바는 **절대 줄어들지 않는다**(도망갔다 와도 이어서 채운다). 화면 하단에 **항상 크게** 표시.
일반 좀비 4마리는 교장 연설에 **자기들도 더 졸려져서 3초간 멈춘다** — 연설은 위협이자 기회다.

**보스에는 체력도 `onDefeat`도 없다.** 이벤트는 `onBroadcastSuccess` 하나뿐이고,
그때 교장이 `"어라? 다들 왜 이렇게 상쾌해 보이지?"`라고 반응한다. (story-builder §4-4 확인)

### M10. 급식표 조각 (수집)

- 스테이지당 **2개**, 총 **10개**. 스테이지마다 1개는 쉬운 자리, 1개는 막다른 길.
- 반경 90px 안에 들어오면 **살짝 반짝**한다. **미니맵에는 표시하지 않는다** — 현장에서 찾는 재미.
- 한 번 먹으면 **영구 저장**. 재시작해도 안 사라진다.

### M11. 미니맵 (v0.2 개정)

- 크기 **132 × 88px**. HUD 상단 띠가 아니라 **게임 캔버스 위 좌상단 반투명 오버레이**.
- 그리는 것 (graphic-designer §4-1 수용 — 단순화):
  - 방 = **단색 채운 사각형 블록** (벽선·문·타일 디테일 전부 생략)
  - 복도 = 가는 회색 막대
  - 남은 재료 = 노란 `!` 마커 / 출구 = 초록 삼각
  - 나 = 흰 점 + 진행 방향 짧은 선
  - 일반 좀비 = **보라 점, 250px 이내만** / 아주머니 = **빨간 사각, 320px 이내만**
  - 급식표 = **표시 안 함**
- **좀비 점은 벽을 무시하고 보인다.** 이건 버그가 아니라 의도다 — 벽에 막힌 하품 소리의 시각적 쌍(§9-0).
- **탭(또는 `M`)하면 전체 지도 오버레이 + 게임 일시정지.** 다시 탭하면 닫힘.
  132×88에 다 못 담는 정보는 여기서 크게 본다. 기다리게 하는 벌이 아니라 계획하는 도구.

## 4. levels[] — 5스테이지 × 3구역 = 15구역

각 구역은 **체크포인트**다. 잠들면 그 구역 시작 지점에서 재개하고, 이미 먹은 재료·급식표는 유지한다.
새 요소는 **구역당 하나만** 들어온다.
구역별 인게임 무전 대사는 `reviews/story-builder.md` §1 표가 정본.

### 스테이지 1 — 「점심시간 끝」 1층: 급식실·보건실·현관
맵 **30×20 타일 (1200×800px)**. 좀비 **3마리** (기본 2 + **배고픈 좀비 1**).
기본 좀비: 순찰 **45 px/s**, 추격 **74 px/s**, 감지 **100px**, `?` 유예 **0.6초**, 포기 **3.5초**.
배고픈 좀비: 순찰 **52**, 추격 **88**, 감지 **110**, `?` **0.6초**, 포기 **3.5초**.
플레이어 **130 px/s**. 재료 2개, 급식표 2개, 사물함 9개, par **90초**.

| 구역 | 새로 나오는 것 | 숫자 | 왜 더 어려운가 |
|---|---|---|---|
| 1-1 현관 → 복도 | 이동, 미니맵 | 좀비 1 (복도, 순찰 45 / 추격 74) | 시작. 좀비 한 마리가 복도를 느리게 지나갈 뿐 |
| 1-2 보건실 (비타민) | **재료 줍기** | 좀비 +1 (보건실, 45/74) | 좀비가 있는 방 **안**으로 처음 들어간다 |
| 1-3 급식실 (고추장) | **사물함 숨기** | **배고픈 좀비 1 (52/88)** + 시야를 막는 급식 테이블 | **처음으로 도망만으로는 안 된다.** 테이블 뒤에서 갑자기 나오고, 코너를 돌면 따라잡힌다 |

**스테이지 1은 여전히 거의 질 수 없다.** 사물함 9개, 타이머 없음, 목숨 없음.
다만 1-3에서 배고픈 좀비가 "숨는다는 선택지"를 아이 머릿속에 심는다.

| 글자 | 뜻 |
|---|---|
| `#` | 벽 (통과 불가, 시야 차단) |

| `,` | 방 바닥 (방마다 색 다름 — 팔레트는 graphic-designer §1) |

| `L` | 사물함 / 신발장 — 통과 불가, **숨기 가능** (청록 하이라이트 테두리) |
| `V` | 재료: 보건실 비타민 |
| `G` | 재료: 매운 고추장 |
| `M` | 급식표 조각 |
| `C` | 분필 더미 (스테이지 1에서는 장식. 2에서 이 자리가 습득 지점) |
| `z` | 기본 좀비 순찰 시작점 |
| `Z` | **배고픈 좀비** 순찰 시작점 (v0.2 신규) |
| `S` | 플레이어 시작 (현관) |
| `E` | 계단 = 출구. 재료 2개를 다 모아야 열린다 |

읽는 법: 왼쪽 위가 급식실, 오른쪽 위가 보건실, 가운데 세로가 중앙 복도(2칸 폭),
한가운데 가로줄(행 10~11)이 1층 복도, 왼쪽 아래가 현관, 오른쪽 아래가 계단실.

**복도는 전부 2타일(80px) 폭이다.** 1타일 복도에서 좀비와 마주치면 대처가 없다 —
2타일이면 옆으로 비껴 지나갈 수 있다. 타협 불가 규칙.
행 1의 `M.` 은 **막다른 골목**이다. 굳이 올라가 본 아이에게 주는 상.
배고픈 좀비(`Z`)의 순찰 경로는 급식 테이블 `T` 블록 **뒤쪽을 지나가게** 잡는다.

### 스테이지 2 — 「5교시」 2층: 4학년 교실들·복도
맵 **34×22 (1360×880)**. 좀비 **5마리** (기본 4 + 아주머니 1).

## 6. failState

**잡히면 죽지 않는다. 같이 잠든다.**

연출 (총 **3.0초**, 시작 후 **0.4초부터 아무 키·탭으로 스킵 가능**):
1. `0.0~1.0s` 주인공 큰 하품 → 눈 스르르. 주변 좀비도 따라 하품.
2. `1.0~2.0s` 하늘에서 베개 툭. 다 같이 쓰러져 `zzz` 말풍선. 화면 약간 어두워짐 + 코 고는 소리.
3. `2.0~3.0s` **딩동댕동** 종소리 → 주인공만 벌떡. `"아 깜짝이야! 얼마나 잤지?"`
4. 하단에 랜덤 한 줄 (10종, `reviews/story-builder.md` §2).

잡은 상대에 따른 변주 (렌더러에서 캐릭터 종류로 분기):
| 변주 | 트리거 |
|---|---|
| 국자로 푸딩 한 입 떠먹여 줌 → "맛있…" | 급식 아주머니에게 잡힘 |
| `"…그리고 세 번째로…"` 자막 | 교장 연설 반경 / 몸통에 잡힘 |
| **「짝꿍과 함께 잠듦」** — 친구와 껴안고 `zzz` 하트 | **친구를 1명 이상 데리고 다니는 상태에서** 일반 좀비에게 잡힘 |
| 기본 (베개) | 그 외 |

> v0.1의 "친구 좀비" 표기는 M7의 구출 대상 친구와 헷갈려서 폐기했다. (story-builder §4-3)

버튼: **「🔔 종 치고 다시!」** 하나뿐. 데스크톱은 `Enter`/`Space`로도 눌린다.

**재시작 규정 (타협 불가):**
- 버튼을 누른 순간부터 조작 가능해지기까지 **300ms 이내**. 페이지 리로드 없음, 에셋 로딩 없음,
  게임 상태 객체만 제자리에서 리셋.
- 재개 지점은 **현재 구역(체크포인트)의 시작**. 스테이지 처음이 아니다.
- **이미 먹은 재료·급식표는 그대로 유지.** 구출한 친구는 그 구역 시작 상태로 복귀(다시 구하면 됨,
  점수는 중복 지급하지 않는다).
- 좀비만 초기 순찰 위치로 돌아간다.
- 최악(스킵 안 함) 3.0초 + 300ms, 스킵하면 **0.4초 + 300ms 미만**.
- 목숨 개념 없음. 무한 재시도. 대기 시간 없음.

## 7. progression

**시작 화면 (첫 실행)**
- 이름 입력: 한글 최대 6자. 추천 이름 버튼 4개(`하린` `서아` `유나` `지우`).
- 외모: 머리색 4종 × 옷색 4종 = 16조합 (색 코드는 graphic-designer §1). 큰 미리보기.
- `localStorage` 저장 → 다음부터 `"{이름}아, 또 왔구나!"` + 바로 이어하기.

**저장되는 것** (`localStorage`, 키 하나에 JSON)
| 키 | 내용 |
|---|---|
| `name`, `look` | 이름, 외모 |
| `unlockedStage` | 해금된 스테이지 (1~5) |
| `stars[5]` | 스테이지별 별 0~3 |
| `best[5]` | 스테이지별 최고 점수 |
| `menuPieces` | 급식표 조각 10칸 (한 번 먹으면 영구) |
| `friendsMet` | 만난 친구 4명 (엔딩 등장 여부) |
| `sleepCount` | 총 잠든 횟수 (엔딩 개그용) |
| `unlockedHats` | 얻은 모자 |
| `bgmOn`, `sfxOn` | **음악/효과음 토글 분리 저장** |

**해금**
- 스테이지 선택 화면. 클리어하면 다음 칸이 열린다. 깬 스테이지는 언제든 재도전.
- **급식표 10개 완성** → 엔딩에 "내가 고른 메뉴"가 급식표에 오름 + 🍓 **딸기 푸딩 모자**.
- 별 누적 해금: 5별 `리본` / 10별 `왕관` / 15별 `급식 모자`.
  모자는 전부 **장식 전용** — 성능 영향 없음. 실력 없는 아이가 밀리면 안 된다.
- **엔딩에 구출한 친구 4명이 등장해 한마디씩 한다** (v0.2, audience 요청).
  못 구한 친구는 그 자리가 비고, 다시 플레이할 이유가 된다.

**내일 또 켤 이유 (v1)**
- 급식표 칸이 비어 있는 게 수집 화면에 회색 실루엣으로 보인다.
- 스테이지별 최고 점수 + 별 3개 도전 (특히 스테이지 4의 친구 4명 전원).
- 엔딩 후 해금: **「연습 모드」** — 좀비 수를 0~최대로 직접 조절해 맵을 마음껏 돌아다니기.

**v2 예정 — 「오늘의 급식」 데일리 챌린지**
audience가 가장 강하게 원한 기능(`"이건 무조건 해야 해!!"`)이지만 **v1에는 넣지 않는다.**
15구역 + 보스가 먼저 재밌어야 하고, 재미의 뼈대가 안 선 상태에서 붙이는 재방문 장치는 빈 껍데기다.
v2 설계는 지금 적어 둔다(잊지 않기 위해):
- 날짜를 시드로 매일 1개 챌린지. 예: `"분필 없이 2스테이지 클리어"`, `"30초 안에 1-3 통과"`,
  `"아무도 안 깨우고 4스테이지 클리어"`.
- 성공하면 급식표에 **그날의 특별 메뉴 칸**이 하루만 켜지고, 주간 7칸을 다 채우면 모자 하나.
- 실패해도 잃는 건 없다. 다음 날 새 챌린지.

## 8. graphic-designer 에게 — 반드시 시각적으로 구분되어야 하는 것

색·실루엣 상세는 `reviews/graphic-designer.md` §1~3이 정본. 여기는 **구분 요구사항**만 남긴다.

**절대 헷갈리면 안 되는 짝:**

1. **졸음 좀비 vs 구출할 친구** — 좀비: 보라 눈 + 반쯤 감긴 눈꺼풀 + **축 늘어진 팔** + 하품 말풍선.
   친구: 또렷한 흰 눈 + **하늘색 `#7FD4FF` 테두리 글로우(고리형, 펄스)** + 손 흔들기.
   **v0.2 변경: 친구 글로우를 노랑 → 하늘색으로.** 노랑은 이미 손전등·연설 범위·급식표·`+점수`에
   쓰여 과포화다. (graphic-designer §5-5 수용)
2. **사물함(숨기 가능) vs 장식 가구** — 숨을 수 있는 것에만 **연한 청록 하이라이트 테두리**,
   가까이 가면 `↓` 아이콘.
3. **재료 vs 급식표 조각** — 재료는 크고 빛나는 실물 아이콘(**타일의 60% 이하** 크기,
   글로우는 아이콘 밖으로 삐져나오게). 급식표는 10개 전부 **똑같은 연노랑 접힌 종이** + 반짝임 파티클.
4. **기본 좀비 vs 배고픈 좀비 vs 급식 아주머니** — 세 단계가 속도 순으로 읽혀야 한다.
   기본: 빈손. **배고픈 좀비: 급식판을 들고 뒤뚱임이 빠름.** 아주머니: 한 덩치 크고(r16)
   빨간 머릿수건 + 흰 앞치마 + 국자 실루엣. **흑백으로 봐도 구분되어야 한다.**
5. **교장 연설 범위 vs 손전등 불빛** — 연설은 **바닥에 깔리는 노란 반투명 원 + 테두리 맥동**,
   손전등은 **위로 뜨는 `#FFF3D6` 부채꼴**. 둘 다 같은 노랑을 쓰지 말 것.
6. **분필 소리 반경 vs 알람시계 소리 반경** — 분필: **얇은 흰 원 1회 퍼짐**.
   알람: **두꺼운 주황 원이 4초간 반복 + 남은 시간이 줄어드는 링**. 지속 여부가 한눈에.
7. **잠긴 문 vs 안 잠긴 문** — 잠기면 자물쇠 아이콘 + 문틀이 파랗게. 남은 횟수 점 3개.
8. **복도 바닥 vs 방 바닥** — 복도는 전 스테이지 공통 회색 리놀륨 + 노란 중앙 점선.
   길찾기의 기준선이다. 방은 방마다 다른 색.
9. **`?` 와 `!`** — 이 게임의 공정성 그 자체. 상세 스펙은 graphic-designer §3 표를 그대로 채택.
   흰/작게/떠오름 vs 빨강/2배/튕김 + 화면 진동 ±2px.
10. **교장의 4단계 상태** (v0.2 신규 — §9-0 뮤트 대응) — 걷기 / 예고 / 연설 / **회복**이
    소리 없이도 구분돼야 한다. 특히 회복 = "지금 가라" 신호다.
11. **어두운 방의 좀비 눈** — 반경 26px 약한 보라 발광. 벽 너머로는 안 보임.
12. **재료 반짝임(따뜻한 노랑) vs 손전등 콘(차가운 흰노랑)** — 손전등 안에서 반짝임이 묻히지 않게.
    (graphic-designer §5-6 수용)

**전체 톤**: 파스텔, 둥근 모서리, 굵은 외곽선 2px. 그림자는 발밑 타원 하나.
어두운 방도 검정이 아니라 **짙은 남보라**. 캐릭터 디테일은 **3개 이하**(몸색 / 눈 / 머리 위 아이콘).
무서운 건 하나도 없다.

### 9-0. 최우선 규칙 — 뮤트 상태로도 전부 클리어 가능해야 한다 (v0.2 신규)

> **소리는 예고, 확정 정보는 항상 시각.**
> 스테이지 1~5 어느 구역도 청각 정보를 **필수**로 요구하지 않는다. 3-3 도서관도 예외가 아니다.

게임플레이 정보를 나르는 모든 소리에는 **시각적 쌍**이 있다:

### 9-1. 음소거 토글 분리 (v0.2, musician §5-5 수용)

- `04.escape_room`처럼 **bgmBus / sfxBus를 나눈다.**
- 일시정지 화면에 토글 **2개**: `음악` / `효과음`. 기본 둘 다 켬. `localStorage` 저장.
- HUD 우상단 ⏸ 옆에 **빠른 음소거 1개**(둘 다 끔/켬)도 둔다 — 급할 때 한 번에.
- 이 게임은 소리가 정보를 나르므로 **"음악만 끄고 효과음은 켜기"가 기본 권장 조합**이다.

### 9-2. 보스 사이클 단축에 따른 재작업 (v0.2)

보스 타이밍이 바뀌었으니 다음 소리의 길이를 맞춰야 한다:
- `bossSpeech` (예고) 1200ms → **1000ms**
- `bossSpeechLoop` (연설) 4000ms → **3500ms** (음절 7~9개)
- `bossCough` 300ms 유지, 회복 구간 2.2초 시작점에 정확히 동기
- 보스 행진곡 루프도 12.2초 사이클에 맞춰 자연스럽게 되감기게

### 9-3. 그 외 수용한 제안

- **졸음 모티프 솔-미-도-라** 재사용 설계(musician §4) — 전면 채택. 아이가 "이 소리 = 졸림"을
  학습하는 게 이 게임의 청각 정체성이다.
- 사물함 안 BGM 로우패스 1200Hz, **곡은 안 바꿈** — 채택.
- `matronClank` 신규 SFX — 채택 (§M8).
- `yawn` 벽 감쇠(로우패스 1500Hz + ×0.5) — 채택.
- `nearMiss`가 추격 중에 튀는 소리로 들릴 위험 — **playtester 확인 항목으로 등록** (§10-5).

### 9-4. iOS 주의

`AudioContext`는 정지 상태로 시작한다. 타이틀 화면 **「시작」 버튼의 실제 `touchend`/`click`
핸들러 안에서** `resume()`을 불러야 한다. 이 프로젝트에서 두 번 깨진 적 있다.

## 10. openQuestions — 빌드 직후 playtester가 확인할 것

v0.1에서 답이 나온 항목(스테이지 1 난이도, `?` 유예, 분필 무한, 친구 페널티, 보스 사이클,
가로 모드, 데일리 챌린지, 급식표 개수)은 **§변경 이력에서 결정 완료**. 남은 것만 적는다.

1. **배고픈 좀비(52/88)가 스테이지 1을 "거의 질 수 없음"에서 벗어나게 했는가?**
   의도는 "숨어볼 이유를 만들되 여전히 안 진다"이다. 1-3에서 아이가 **두 번 이상** 잠들면 과하다
   → 추격 88 → 84로 내린다.
2. **친구 미끼 메커닉이 "친구를 일부러 희생시키는" 플레이로 변하지 않는가?**
   페널티를 없앤 대신 친구가 방패가 됐다. 아이가 친구를 고의로 좀비 앞에 밀어 넣으며 웃는다면
   그건 귀여운 창발이지만, "안 깨우고 버리는" 게 최적해가 되면 정서적으로 안 좋다.
   → 그렇게 나오면 **스테이지 종료 시 친구 전원 각성 보너스(+1000)**를 추가한다.
3. **보스 12.2초 사이클이 이제 너무 촉박하지 않은가?** 5.5초 걷기 + 34 px/s로 압박을 보정했는데,
   방송 게이지 3.0초를 세 번 나눠 채우기에 안전 창 7.7초가 빠듯할 수 있다.
   → 빠듯하면 연설 3.5 → 3.2초.
4. **재료 8개 HUD 줄이 390px에서 읽히는가?** 8칸 × 약 28px = 224px. 이론상 들어가지만
   실제로 "뭘 더 모아야 하는지" 한눈에 읽히는지 확인 필요. 안 읽히면 4+4 두 줄.
5. **`nearMiss` 소리·흰 섬광이 추격 중에 놀라게 하지 않는가?** (musician §5-6)
6. **스테이지 4 줌아웃(0.8)에서 캐릭터가 너무 작지 않은가?** 폰 실측 지름이 약 17px까지 내려간다.
   graphic-designer의 "디테일 3개 이하" 규칙이 여기서도 버티는지 확인.
7. **전체 지도(미니맵 탭 → 일시정지)를 아이가 발견하는가?** 발견 못 하면 1-1에서 무전으로 한 번
   알려준다: `"지도를 눌러 봐. 어디가 어딘지 다 보여!"`
8. **뮤트 상태 클리어 검증** — playtester는 **스테이지 3-3과 5-3을 소리 완전히 끈 채로** 한 번씩
   클리어해 봐야 한다. 이게 §9-0 규칙의 실제 검증이다.

## 11. 빌더 편차 판정 (v0.3)

`docs/BUILD_NOTES.md` §2의 편차 10건에 대한 판정이다.
**수락**이면 이 문서(§0~§10, 부록 A)를 코드에 맞춰 이미 고쳤다 — 스펙과 코드가 지금 일치한다.

### 11-B. 반려 — 빌더가 고쳐야 할 것

우선순위 순이다. **1·3번이 커브를 실제로 깨는 것이고, 나머지는 마감이다.**

---

**B-1. 스테이지 2 아주머니가 2-1부터 복도 전체를 쓸고 다닌다 — 「구역당 새 요소 하나」 위반**

- 현상: `matronPaths[0]`이 `x 2.5 ↔ 31.5`, 즉 복도 **전 구간**이다. 그런데 2-1의 `zone`이
  `{x:1,y:9,w:32,h:2}`(같은 복도)이고 `spawn`이 `(3.5, 10.5)`다.
  → **분필을 배우는 구역에서 아주머니를 동시에 만난다.** 2-2의 무전
  `"국자 아주머니는 빨라!"`는 이미 만난 뒤에 나온다.
- 고칠 것: 아주머니는 **복도 오른쪽 끝(x≈31)에 서서 하품만 하고 있다가,
  플레이어가 분필(`C`)을 줍는 순간 순찰을 시작한다.**
  경로 자체는 지금 것을 그대로 쓰면 된다 — 시작 조건만 붙이면 된다.
- 왜 이 방식인가: 맵도 구역도 안 건드린다. 그리고 "분필을 주웠더니 저 멀리서 국자 소리가
  나기 시작한다"는 **기억에 남는 한 장면**이 공짜로 생긴다.

---

**B-2. 1-3 배고픈 좀비의 순찰 경로가 자동 생성이다**

- 이 좀비의 존재 이유는 속도가 아니라 **"급식 테이블 뒤에서 시야가 막힌 채 갑자기 나온다"**이다
  (§M1-b). BFS로 방 안 먼 지점 3곳을 이으면 그게 보장되지 않는다.
- 고칠 것: `Z`의 웨이포인트만 손으로 찍는다. 급식실 테이블 블록
  (`MAP1` 행 2~3의 `TTT` 두 덩어리) **뒤쪽을 지나가는 8자 경로**로.
- 나머지 일반 좀비는 자동 생성 그대로 둔다.

---

**B-3. 스테이지 3 — 손전등을 배우는 3-2 미술실을 통째로 건너뛸 수 있다 (가장 중요)**

- 현상: 재료가 `O` 큰북(음악실) + `J` 웃긴 책(**도서관**)이고, 출구 `EE`는 **복도**(행 10~11, 열 33~34)에 있다.
  → 미술실에는 급식표 하나뿐이라 **안 들어가도 클리어된다.**
  그러면 아이는 어둠을 연습하지 못한 채 3-3 도서관(어둠 + 좀비 3 + 책장 미로)에 들어간다.
  이건 내 커브 규칙 「새 요소 뒤에는 반드시 연습 구역을 한 번 준다」의 정면 위반이다.
- 고칠 것 (`MAP3`, 세 군데):
  1. **`J`(웃긴 책)를 도서관 → 미술실로 옮긴다.** (예: 행 7, 열 30 근처의 `,`)
  2. **출구 `EE`를 복도 → 도서관 안쪽으로 옮긴다.** (예: 행 20~21, 열 32~33)
     복도의 기존 `EE` 자리는 그냥 복도 바닥 `.`으로.
  3. 결과 동선: 음악실(큰북·알람) → 미술실(웃긴 책·손전등 연습) → 도서관(출구). **세 방 전부 필수, 순서도 고정.**
- 같이 고칠 것 — **좀비 배분 (총 6 + 아주머니 1 = 7은 그대로)**:
  - **음악실 1 → 2마리.** 알람시계를 처음 쓰는 방인데 1마리면 "싹 다 몰려온다"가 안 보인다.
    분필과 구분이 안 된다. 이 구역의 존재 이유가 사라진다.
  - **미술실 2 → 1마리.** 어둠을 처음 만나는 연습 구역이다. 한 마리로 충분하다.
  - 도서관 3마리·아주머니 복도 순찰은 그대로.
  - 합계 2 + 1 + 3 + 아주머니 1 = **7** ✓ (부록 A와 일치)
- 참고: 이 배분은 BUILD_NOTES §2-2의 "3-1이 너무 심심하면 2로 올릴 것"에 대한 답이기도 하다 —
  playtester를 기다리지 말고 **지금 2로 올린다.**

---

**B-4. 스테이지 4 — 마지막 구역이 첫 구역보다 적이 성기다**

- 현상: 체육관(4-1) 기본 4마리 / 운동장(4-3) 기본 3마리 + 아주머니 1.
  면적은 체육관 23×13 = 299칸, 운동장 42×14 = 588칸.
  → **클라이맥스의 밀도가 도입부의 절반 이하다.** 4-3은 "숨을 곳이 없어서 도구를 써야 뚫리는 곳"인데
  지금 숫자로는 그냥 걸어서 가로지른다.
- 고칠 것: **체육관 `z` 한 마리를 운동장으로 옮긴다.** 총합 10은 그대로.
  - 4-1 체육관 **3** / 4-2 창고 **1 + 아주머니 1** / 4-3 운동장 **4 + 아주머니 1**
  - `MAP4`에서 `(13,19)`의 `z`를 지우고 운동장 가운데(예: 행 22, 열 24 근처)에 하나 추가.
- 더 조일지는 playtester 결과를 보고 정한다. 지금은 **순서만 바로잡는다.**

---

**B-5. 어두운 방 밖에서 방 안 엔티티가 보이면 안 된다**

- §11-A-8의 조건. 복도에서 도서관을 들여다봤을 때 **어두운 바닥색은 보여도 되지만,
  그 안의 좀비·재료·급식표·친구는 그리지 않는다.**
- 이미 그렇게 구현돼 있으면 아무것도 안 해도 된다. 확인만 부탁한다.

---

**B-6. 잠긴 문 두드리기(`knock`)가 안 붙어 있다**

- §M5에 "좀비는 잠긴 문을 두드리다 다른 길로 돌아간다"고 적혀 있다.
  지금은 말없이 돌아가서 **문을 잠근 게 효과가 있었는지 알 수 없다.**
- 고칠 것: 잠긴 문에 막힌 좀비가 경로를 다시 잡을 때 문 앞에서 **0.6초 멈추고 `knock` 3회** +
  문틀이 세 번 흔들린다. `audio.ts`에 `knock`은 이미 있다.
- 이건 정보성 소리가 아니라 **보상 피드백**이다. 뮤트 대응(§9-0)은 문틀 흔들림이 담당한다.

### 11-C. 표 불일치 정리 (§4 구역 표 ↔ 부록 A)

빌더 지적이 맞다. v0.2의 구역 표를 그대로 더하면 스테이지 3이 부록 A보다 1마리 많았다
("3-1 좀비 2 / 3-2 +2 / 3-3 +3" = 기본 7인데 부록 A는 기본 6 + 아주머니 1 = 7).
스테이지 2의 "+1 아주머니"도 "기본 1마리 추가 **및** 아주머니"인지 "추가되는 1마리가 곧 아주머니"인지
읽는 사람마다 달라지는 표기였다.

**정리 규칙 (이제부터 고정):**
- **부록 A의 `ZOMBIE_COUNT`가 정본이고, 그 숫자는 아주머니를 포함한 총합이다.**
- §4 구역 표는 "기본 N" / "아주머니 1"을 **따로** 적는다. "+1 아주머니" 같은 표기는 쓰지 않는다.
- 부록 A에 **구역별 내역 한 줄**을 추가했다. 두 표의 합이 다르면 그건 스펙 버그다.

|---|---|---|
| 1 | 1-1 **1** / 1-2 **1** / 1-3 **1**(배고픈) | **3** ✓ |
| 2 | 2-1 **1** / 2-2 **1 + A** / 2-3 **2** | **5** ✓ |

### 12-A. 「좀비가 다 똑같이 생겼다」 — **수락 (조건부)**

이전에 거절한 것은 **모자·이름**이었고, 그 이유는 "적은 한눈에 구분돼야 한다"였다.
그 판단은 지금도 유효하다. 하지만 아이가 말한 건 "좀비를 구분하고 싶다"가 아니라
**"복제 인간처럼 보인다"**이다. 이건 다른 문제고, 실루엣을 안 건드리고도 고칠 수 있다.

**절대 조건 — 흑백 실루엣 테스트**
> 아래 변주를 전부 적용한 기본 좀비 4마리를 **검정 실루엣으로만** 그렸을 때
> 서로 구분되지 않아야 하고, 배고픈 좀비·아주머니·교장과는 **한눈에 구분되어야** 한다.
> 이 테스트를 통과하지 못하는 변주는 넣지 않는다.

**넣을 것 (기본 좀비 `z` 에만 적용. 배고픈 좀비·아주머니·교장·친구는 제외):**

| # | 변주 | 왜 안전한가 |
|---|---|---|
| 1 | **애니메이션 위상 분리** — 좀비마다 뒤뚱임·하품 주기에 고정 오프셋(0~2π)과 진폭 배율(×0.85~1.15)을 준다 | 형태도 색도 안 바뀐다. **"다 똑같다"는 인상의 실제 원인은 대부분 다 같은 박자로 흔들리는 것이다.** 가장 싸고 효과가 크다 |
| 2 | **하품 말풍선 문구 3종 로테이션** — `하암…` / `숙제…` / `zzz` (좀비별 고정) | 말풍선은 이미 있다. 글자만 바꾼다. 스토리(`"숙제… 숙제…"` 중얼거림)와도 맞는다 |
| 3 | **앞머리 3종** — 몸통 캡 **윤곽선 안쪽에만** 그리는 어두운 아치 (일자 뱅 / 옆가르마 / 뿔 두 개) | 윤곽 밖으로 한 픽셀도 나가지 않으므로 실루엣이 동일하다. 색은 **몸 색을 어둡게 한 단일 톤**만 쓴다 — 새 색을 추가하지 않는다 |

**넣지 말 것:** 모자, 이름표, 몸 색 변주, 눈 색 변주, 크기 변주, 소품(가방·안경 등).
전부 실루엣이나 색으로 "이건 다른 종류의 적"이라는 잘못된 신호를 준다.

`?`/`!` 때 눈이 커지는 연출은 이미 들어가 있다(graphic-designer 작업분). 그대로 둔다 —
**표정은 "상태"를 나타내고, 위 3종은 "개체"를 나타낸다.** 두 축이 섞이지 않는 게 중요하다.

담당: graphic-designer (`sprites.ts`의 `drawZombie`). 좀비 개체마다 고정 시드가 필요하니
`engine.ts`의 좀비 생성 시 `variant: 0|1|2`와 `phase: number`를 한 번만 뽑아 들고 있으면 된다.

### 12-B. 「사물함 안이 안 보여서 무섭다」 — **수락 (인식 문제, 시각으로 해결)**

사물함은 **스펙상 항상 100% 안전하다**(§M2). 규칙을 바꿀 이유는 없다.
문제는 규칙이 아니라 **그 사실이 화면에 안 적혀 있다**는 것이다.
그리고 이건 그냥 기분 문제가 아니다 — 아이가 숨기를 망설이면 1-3부터 5-3까지
설계의 절반이 안 쓰인다. **고쳐야 한다.**

고칠 것:
- 상호작용 대상으로 잡힌 사물함(가장 가까운 하나, 34px 이내)의 문이
  **약 15% 열린 채로 그려진다.** 안쪽에 **따뜻한 크림색 빈 공간**(`#FFE9B8` 계열)이 보인다.
- 지금 있는 `↓` 아이콘과 청록 하이라이트 테두리는 그대로 둔다.
- 여러 개가 가까이 있어도 **열리는 건 실제 대상 하나뿐이다.** 어느 칸에 들어갈지도 같이 알려준다.

왜 이 방식인가: 새 UI를 하나도 안 늘리고, **"안이 비었다 = 들어가도 된다"가 그림 하나로 전달된다.**
그리고 §M2가 이미 쓰고 있는 언어 — "숨으면 문틈으로 밖이 보인다" — 의 정확한 반대편이라
배우는 데 설명이 필요 없다.

담당: graphic-designer (`drawLockerTile`에 `highlighted` 상태 추가).

### 12-C. 「엔딩에 친구 4명이 다 안 보인다」 — **이미 구현됨. 다만 빈자리를 보이게 고친다**

먼저 사실관계: **구현돼 있다.** `EndingScreen.tsx`가 `FRIENDS`를 돌면서 구출한 친구를
`drawFriend`로 그리고, 그 친구의 대사(`f.line`)도 엔딩 대사 줄에 넣는다.
아이가 본 화면은 **아무도 구출하지 않은 테스트 런**이었을 가능성이 높다.

그런데 코드를 보면 진짜 문제가 하나 있다:

```
FRIENDS.forEach((_, i) => { if (!friendsMet[i]) return; ... });
const met = friendsMet.filter(Boolean).length;
const slots = met + 1;
```

**못 구한 친구는 자리 자체가 사라지고 레이아웃이 다시 가운데 정렬된다.**
그래서 0명이면 주인공만 덩그러니 서 있고, 아이 눈에는 "친구가 안 나온다 = 버그"로 보인다.
빈자리가 안 보이면 "다시 해서 채워야지"라는 동기도 안 생긴다 —
§7에 적어 둔 `"못 구한 친구는 그 자리가 비고, 다시 플레이할 이유가 된다"`가 작동하지 않는다.

고칠 것 (`EndingScreen.tsx`):
- **슬롯은 항상 5개**로 고정한다: 주인공 1 + 친구 4. `slots = 5`, 레이아웃 재정렬 없음.
- 구출한 친구: 지금처럼 컬러 + 하늘색 글로우 + 손 흔들기.
- **못 구한 친구: 같은 자리에 회색 실루엣으로 누워서 `zzz`** (급식표 수집 화면의 회색 실루엣과 같은 언어).
  머리 위에 그 친구 이름을 작게 띄운다.
- 엔딩 대사 줄에 한 줄 추가 — 못 구한 친구가 있을 때만:
  `"아직 자고 있는 친구가 {n}명 있대. 다시 가 볼까?"`
- 4명 전원 구출 시: 다섯이 나란히 서서 손 흔들고, 한 줄 추가 —
  `"{이름}이랑 친구들 넷, 다 같이 학교를 구했다!"`

이러면 아이의 요구("4명이 다 보였으면")와 §7의 설계(빈자리가 재플레이 동기)가 동시에 충족된다.
**보이긴 다 보이되, 안 구한 애는 자고 있다.**
