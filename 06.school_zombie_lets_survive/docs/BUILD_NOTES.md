### 이동·충돌 (§0)
- **자유 8방향 이동** (칸 단위 아님). float 픽셀 좌표 + 원형 충돌체.
- 충돌은 원 vs 타일 AABB, **축 분리** 처리 + 코너 보정 12px.
- 벽 끼임 방지 안전망 `unstick()` — 어쩌다 벽 안에 들어가면 가장 가까운 빈 자리로 밀어낸다.
  (플레이테스트용 랜덤 조작 25초 × 5스테이지에서 벽 끼임 0회 확인)
- 카메라 `cam += (target-cam)*0.15`, 맵 경계 clamp, 그릴 때 카메라 오프셋만 `Math.round`.
- 스테이지 4는 `renderScale 0.8` 자동 줌아웃 (15×20 타일 시야).

### 2-4. DESIGN §12 (audience v2) 반영 — 4차

우선순위대로 12-C → 12-B → 12-A 순으로 넣었다.

**12-C 엔딩 슬롯 5개 고정** (`EndingScreen.tsx`)
- 자리는 **항상 5개**다: 주인공 1 + 친구 4. 레이아웃 재정렬 없음(`SLOTS = 5`).
- 구출한 친구는 컬러 + 하늘색 글로우 + 손 흔들기, **못 구한 친구는 같은 자리에 회색으로 누워
  `zzz` + 이름**(`sprites.ts`의 새 `drawSleepingFriend`). 급식표 수집 화면의 회색 실루엣과 같은 언어다.
- 대사 두 줄 추가(`text.ts`): 못 구한 친구가 있으면 `"아직 자고 있는 친구가 {n}명 있대. 다시 가 볼까?"`,
  4명 전원이면 `"{이름}이랑 친구들 넷, 다 같이 학교를 구했다!"`.
- 캔버스를 130 → 152px로 키우고 인물 줄을 내렸다 — 글로우 고리가 잘리고 이름이 바닥에 묻히던 걸 같이 고쳤다.
- 스크린샷: `docs/screenshots/ending-zero-rescue.png`(0명), `ending-all-four.png`(4명).

**12-B 사물함 문 살짝 열기** (`sprites.ts` / `renderer.ts`)
- 상호작용 대상으로 잡힌 **그 한 칸만** 문이 약 15% 열리고 안쪽에 따뜻한 크림색 빈 공간이 보인다
  (`drawLockerAjar`). 숨어 있는 상태(`drawLockerOpenOverlay`)와는 **별개의 그림**이다 — 이건 "들어오기 전".
- `↓` 아이콘·청록 테두리·사물함 안전 규칙(§M2)은 그대로.
- 스크린샷: `docs/screenshots/locker-ajar.png` (신발장 4칸 중 맨 왼쪽 하나만 열림).

**12-A 좀비 개체 변주** (`types.ts` / `engine.ts` / `sprites.ts`)
- 좀비마다 태어날 때 한 번만 뽑는 `variant: 0|1|2` · `phase`(0~2π) · `bobAmp`(0.85~1.15).
  **기본 좀비 전용** — 배고픈 좀비·아주머니·교장·친구는 전부 제외(아주머니는 `variant 0 / phase 0 / amp 1`로 고정).
- (a) 뒤뚱임·하품 박자가 개체마다 어긋난다. (b) 하품 말풍선 문구 `하암…` / `숙제…` / `zzz` 고정 로테이션.
  (c) 앞머리 3종(일자 뱅 / 옆가르마 / 뿔 두 개)을 **몸통 path로 클립해서 윤곽선 안쪽에만** 그린다.
  색은 몸 색을 0.72배 어둡게 한 단일 톤 하나뿐 — 새 색을 추가하지 않았다.
- **§12-D 몸통 라운드**: 캡슐을 위·아래 **타원 캡**(`bodyPath`)으로 바꿔 "눈 달린 파란 사물함"에서 벗어났다.
  플레이어·친구도 같은 몸통을 쓰므로 톤이 유지된다.
- **흑백 실루엣 테스트 통과** — `docs/screenshots/silhouette-test.png`.
  전부 한 색으로 눌러 그린 뒤 픽셀 차이를 쟀다: 기본 좀비 4마리는 기본1 대비 **0.2 / 0.4 / 0.8%**
  (전부 뒤뚱임 위상 차이일 뿐 형태 차이가 아니다), **배고픈 좀비는 9.4%**로 한눈에 다르다.
  아주머니·교장도 명확히 구분되고, 같이 그린 **사물함 타일**과도 안 헷갈린다.
- 함정 하나: 씨앗 기반 LCG는 이웃한 씨앗의 **첫 출력이 붙어 있어서** 한 스테이지 좀비가 전부
  같은 앞머리로 나왔다. 난수를 두 번 버리고 쓰도록 고쳤다 (스테이지 3 = `2,0,1,1,2,0` / 4 = `1,2,0,0,1,2,0,0`).

**12-D 옷색 8종**은 판정대로 그대로 둔다.

### 2-8. 난이도 쉬움 / 보통 / 어려움 (DESIGN §15)

**보통 = v0.6의 숫자 그대로.** 기존 저장은 전부 보통으로 취급한다.

새 파일 `difficulty.ts`가 정본이다. 상수를 건드리지 않고 **판이 만들어질 때 숫자를 굳혀서**
`GameState.tune`에 들고 있는다 (`makeTuning(difficulty, stage)`). 그래서 난이도를 바꿔도
다른 판·다른 저장에 영향이 없고, **시작한 판의 난이도는 못 바뀐다**(기록 오염 방지).

가드레일은 상수로 박았다: `CHASE_SPEED_CAP = 118`, `NOTICE_DELAY_FLOOR = 0.35`.

#### 실측 (스테이지 1, 디버그 훅으로 확인)

| | 쉬움 | 보통 | 어려움 |
|---|---|---|---|
| 순찰 / 추격 / 감지 | 34 / 53 / 75 | 45 / 74 / 100 | 52 / 83 / 120 |
| `?` 유예 / 포기 | 0.95초 / 2100 | 0.60초 / 3500 | 0.45초 / 4900 |
| 잡힘 / 보스 잡힘 | 16 / 24 | 20 / 28 | 23 / 31 |
| 알람 최대 / 분필 CD | 5 / 800 | 3 / 1200 | 2 / 1500 |
| 어둠 시야 / 손전등 배수 | 210 / 1.20 | 150 / 1.35 | 120 / 1.45 |
| 방송 / 보스 이동 / 졸음 반경 | 2000 / 24 / 150 | 3000 / 34 / 200 | 3500 / 40 / 230 |
| 점수 배수 | ×1.0 | ×1.0 | **×1.5** |

전부 §15-1 표와 일치한다. 보스 사이클 4구간(5500/1000/3500/2200)은 세 난이도에서 동일하다.

#### 그 밖에 확인한 것

- **좀비 구성**: 쉬움 스테이지 1에 배고픈 좀비 0마리(일반으로 강등, 총 3마리 유지) /
  어려움 스테이지 2가 `hungry,basic,basic,matron,basic` — **총 5마리 그대로**, 1마리만 교체됨.
- **쉬움 전용 규칙**: 시야가 끊기는 순간 `chase → investigate`. 보통은 `chase` 유지 (실측 확인).
- **기록**: 난이도별로 따로 저장되고 보드는 **지금 고른 난이도의 줄만** 보여 준다 →
  왕관이 난이도를 넘지 않는다. 각 줄에 난이도 뱃지. 현재 이름 줄의 배경 칩(§2-6)은 그대로.
- **마이그레이션**: v2 형식(`records[이름].best/bestTimeMs`)이 `normal` 칸으로 자동 이관된다.
  실측: 하린 4000점/52초가 보통 보드에 그대로 보임.
- **`lastDifficulty`**: 이름을 「서아」로 바꾸니 난이도가 자동으로 `hard`로 복귀 (자매 교대 시나리오).
- **피커 위치**: 스테이지 선택 화면, 연습 모드 상자 **바로 위**. 새로고침해도 선택이 유지된다.
- **상단 띠 뱃지**: 390px에서 `급식표 n/10 · 환풍구 n/8` 아래 줄에 `[난이도] 구역이름`.
  넘침 0 (실측). 쉬움=초록, 보통=회색, 어려움=분홍.
- 스크린샷: `diff-picker.png` · `diff-records-normal.png` · `diff-records-hard.png` ·
  `diff-hud-easy.png` · `diff-hud-hard.png`

#### 편차 (스펙에 안 적혀 있어 내가 정한 것)

1. **다온의 분필 쿨다운을 난이도에 비례시켰다.** 스펙의 「1.2초 → 0.7초」는 보통 기준이라,
   같은 비율(×0.583)을 적용해 쉬움 467 / 보통 700 / 어려움 875로 했다.
   고정 700으로 두면 어려움에서 다온 하나가 난이도 조정을 통째로 되돌린다.
2. **시작 알람이 0인 스테이지(1·2)는 세 난이도 모두 0**이다. 알람은 스테이지 3부터 쓸 수 있어서
   쉬움 +2를 줘도 못 쓰고, 어려움 「최소 1」을 그대로 적용하면 오히려 없던 알람이 생긴다.
3. **점수 ×1.5는 클리어 정산에서 총점에 한 번 곱한다** (항목별로 곱하지 않는다).
   클리어 화면에 `어려움 보너스 ×1.5` 줄을 따로 보여 줘서 숫자가 튀는 이유가 보이게 했다.
4. **어려움의 「일반 1마리 → 배고픈 좀비」 교체 대상은 맵 스캔 순서상 첫 번째 일반 좀비**다.
   결정적이라 매번 같은 자리에서 바뀐다.
5. **아주머니·배고픈 좀비의 `GIVEUP_MS`는 기본 좀비와 같은 배수**(쉬움 ×0.6 / 어려움 ×1.4)를 썼다.
   §15-1 표에는 순찰·추격·감지만 있어서 포기 시간은 비워져 있었다. 아주머니의 `?` 유예(0.45초)는
   표에 없어 세 난이도 모두 그대로 뒀다.
6. **기록 마이그레이션은 지연 적용**이다 — 불러올 때 메모리에서 변환하고, 다음 저장 때 새 형식으로
   기록된다. 업데이트만 하고 한 판도 안 하면 파일은 옛 형식 그대로 남지만 화면에는 정상적으로 보인다.

## §2-7 사물함에서 나갈 방향 고르기 (2026-09-13, 부모 요청)
- 숨어 있는 동안 방향키/조이스틱을 밀면 사물함 옆에 큰 화살표가 그쪽을 가리킨다. 나갈 수 있는 쪽엔 흐린 화살표 힌트.
- 같은 방향을 0.45초 계속 밀면 손 버튼 없이 그쪽으로 나간다 (링이 차오름). 살짝 건드린 정도로는 안 나간다.
- 방향을 고른 뒤 손 버튼을 눌러도 그쪽으로 나간다. 안 고르면 들어오기 전 자리로.
- 막힌 쪽(옆 사물함, 벽)은 빨간 흐린 화살표, 아무리 밀어도 안 나간다.
- 코드: `engine.ts` updateHideAim / lockerExitSpot, `renderer.ts` drawHideExitArrows, 상수 `HIDE_AIM_EXIT_MS`, `HIDE_EXIT_DIST`.
- 검증: 헤드리스 아이폰에서 실제 키 입력으로 왼쪽 홀드 탈출, 아래 선택+손 버튼 탈출, 막힌 오른쪽 미탈출 모두 통과. `docs/screenshots/hide-exit-arrow.png`.
