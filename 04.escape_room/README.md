# 달빛 성 탈출 (Escape Room)

위에서 내려다보는 2D RPG 맵을 돌아다니며, 방마다 숨은 수수께끼를 풀고 다음 방으로
넘어가는 방탈출 게임. 한 스테이지는 방 5개로 이루어지고, 다섯 방을 모두 풀어야 클리어.

**스테이지 5개, 방 25개.** 시작 화면에서 캐릭터(4명)와 이름을 정하고 스테이지를 고른다.

| 스테이지 | 방 |
|---|---|
| 1. 달빛 성 | 먼지 쌓인 현관 · 속삭이는 도서관 · 시계탑 · 거울의 방 · 달빛 옥상 |
| 2. 잠긴 지하 감옥 | 눅눅한 감방 · 간수실 · 먼지투성이 창고 · 물 새는 하수구 · 종탑 계단 |
| 3. 물에 잠긴 서고 | 얕은 물가 · 젖은 서고 · 분수대 광장 · 등불 복도 · 나룻배 선착장 |
| 4. 반짝이는 얼음 궁전 | 얼음 현관 · 서리 정원 · 눈사람 광장 · 고드름 복도 · 오로라 발코니 |
| 5. 별빛 정원 | 덩굴 대문 · 반딧불이 숲 · 요정 연못 · 별자리 계단 · 하늘 전망대 |

## 다섯 가지 퍼즐

| 방식 | 푸는 법 |
|---|---|
| `order` | 물건 4개의 **남은 길이를 비교해** 짧은 것부터 켜기 (추리) |
| `quiz` | 유령이 내는 수수께끼 4지선다 |
| `sequence` | 종이 울린 순서 그대로 밟기 (기억) |
| `code` | 방에 흩어진 숫자 3개를 찾아 문 자물쇠에 입력 |
| `push` | 별 상자를 달 표식 위로 밀기 (소코반) |

스테이지마다 다섯 퍼즐을 **다른 순서로** 배치해서, 같은 방식이라도 흐름이 달라진다.

## 판마다 달라지는 것

같은 스테이지를 다시 해도 똑같지 않다.

- **물건 자리** — 촛대·상자·장식이 매번 다른 칸에 놓인다
- **수수께끼** — 10개 중 하나가 뽑히고, 보기 순서도 섞인다
- **정답 순서** — 어느 색 촛대가 제일 짧은지 매번 달라진다
- **자물쇠 숫자** — 세 자리 숫자도, 어느 물건이 갖고 있는지도 새로 뽑힌다
- **상자 배치** — 밀기 퍼즐은 검증된 배치 3종 중 하나

뽑은 배치가 정말 풀리는지는 `rooms.ts`의 `isSolvable()`이 확인한다 — 문과 물건에
걸어서 닿을 수 있는지 BFS로 검사하고, 안 되면 다시 뽑는다.

## 실행

```bash
npm run dev      # http://localhost:3000
npx next build   # 타입 오류 확인
```

## 조작

- **걷기** — 방향키 / WASD, 또는 화면 아래 십자 버튼 (누르고 있으면 계속 걷는다)
- **살펴보기** — Space / Enter, 또는 🔍 버튼. 바라보고 있는 칸의 물건을 조사한다.
  지금 어느 칸을 보고 있는지는 캔버스에 네모 테두리로 표시된다.
- 아직 안 살펴본 물건 위에는 **?** 가 떠 있다.
- 물건을 살펴보면 **확대 화면**이 뜬다. 그림이 크게 보이고, 먼지·거미줄·긁힌 자국처럼
  가까이서만 보이는 것들이 나타난다. 숨은 숫자나 열쇠도 여기서 드러난다.
  Space / Enter / Esc 나 「그만 보기」로 닫는다.

## 코드 구조

`src/app/game/` 아래, 저장소 공통 규칙을 따른다.

| 파일 | 역할 |
|---|---|
| `types.ts` | 방·퍼즐·게임 상태 타입 |
| `constants.ts` | 격자 크기, 속도, 방별 색 테마 |
| `stageData.ts` | **다섯 스테이지의 대본** — 방 이름·테마·글·퍼즐 종류 |
| `rooms.ts` | 대본을 받아 실제 방을 뽑아 내는 공장 (배치 랜덤 + 풀림 검증) |
| `riddles.ts` | 수수께끼 10개 |
| `engine.ts` | 이동·충돌·상자 밀기·퍼즐 판정 |
| `background.ts` | 방마다 바닥·벽·장식을 한 번 구워 두고 캐시 (매 프레임 복사만 한다) |
| `renderer.ts` | 캔버스 그리기 (어둠, 조명, 파티클, 움직이는 것들) |
| `sprites.ts` | 캐릭터와 물건 그림 (전부 Canvas 2D) |
| `closeups.ts` | 물건을 확대해서 본 그림 — 스프라이트를 키우고 자잘한 흔적을 덧그린다 |
| `audio.ts` | Web Audio 효과음, iOS 오디오 잠금 해제 |
| `GameCanvas.tsx` | 게임 루프, 키보드 입력, HUD |
| `TouchControls.tsx` | 터치 십자 버튼과 살펴보기 버튼 |
| `PuzzlePanel.tsx` | 수수께끼·숫자 자물쇠 패널 |
| `InspectPanel.tsx` | 물건 확대 화면 (보기 / 행동 버튼) |

이미지·오디오 파일은 하나도 쓰지 않는다. 그림은 Canvas 2D, 소리는 Web Audio로 그때그때 만든다.

## 방을 새로 만들려면

`rooms.ts`에 `RoomDef` 하나를 추가하면 된다. 지도는 15×11 문자 격자다.

```
#  벽          .  바닥        S  시작 위치     D  다음 방으로 가는 문
B  책장(막힘)   1~4 바닥 종    X  달 표식       O  별 상자 시작 위치
```

퍼즐은 `puzzle` 필드로 다섯 종류 중 하나를 고른다 — `order` / `quiz` / `sequence` /
`code` / `push`. 물건(`props`)은 `id`로 퍼즐과 연결된다. 예를 들어 `order` 퍼즐의
`sequence`에 적힌 순서대로 촛대를 켜야 `chestId`의 상자가 열린다.

**퍼즐을 만들 때의 원칙**: 정답 후보가 몇 개뿐이면 아이는 추리하지 않고 전부 눌러 본다.
1번 방이 처음에 그랬다 — 물건 여섯 개 중 하나에 열쇠가 있어서 한 번씩 눌러보면 끝났다.
지금은 순서(24가지)를 맞혀야 하고 틀리면 처음부터라, 관찰하는 쪽이 확실히 빠르다.
단서는 **그림에 드러나야** 한다. 초의 남은 길이(`burn`)를 글로만 적고 그림은 똑같이
그렸더니, 확대 화면이 글자 읽는 창이 되어 버렸다.

물건에는 `name`(확대 화면 제목), `say`(설명), `detail`(확대해야 보이는 한 줄)을 달 수
있다. `detail`은 "자세히 보니…" 뒤에 붙으므로, 확대해야만 알 수 있는 관찰이어야 말이 된다.
확대 그림 자체를 손보려면 `closeups.ts`의 `detailPass`에 그림 종류별 가지를 추가한다.

**스테이지를 더 추가하려면** `stageData.ts`에 `StageSpec` 하나를 적고 `constants.ts`의
`STAGES`에 카드 정보를 넣으면 된다. 방을 그리는 코드는 손댈 필요가 없다 — 테마는
`THEMES`에 색과 `floorStyle`/`wallStyle`/`decor`만 지정하면 되고, 바닥 재질 8종
(돌·마루·철판·대리석·기와·물·얼음·잔디)과 벽 5종은 이미 구현돼 있다.
바닥·벽 무늬는 `background.ts`에 테마별 함수로 들어 있다 — 돌 슬래브, 나무 마루, 철판,
대리석, 기와. 새 테마를 넣으려면 바닥 함수 하나와 `wallBlock`의 가지 하나를 추가한다.

배경은 방마다 한 장씩 미리 그려 캐시하므로, 무늬를 아무리 촘촘히 넣어도 매 프레임
비용은 `drawImage` 한 번으로 고정된다. 대신 **방 안에서 변하는 것은 배경에 넣으면 안 된다** —
종, 달 표식, 문처럼 상태에 따라 달라지는 것은 `renderer.ts`에 남겨 둔다.

## 플레이테스트

`.playtest/playtest.mjs`는 Playwright로 실제 브라우저를 띄워 다섯 방을 처음부터 끝까지
자동으로 클리어한다. 아이폰 세로(390×844), 가로(844×390), 데스크톱을 모두 확인하고,
조작 버튼이 화면 밖으로 밀려나지 않는지·퍼즐 패널이 잘리지 않는지도 검사한다.

```bash
npx next dev -p 3104     # 먼저 띄워 두고
node .playtest/playtest.mjs
```

스크린샷은 `.playtest/shots/`에 남는다.
